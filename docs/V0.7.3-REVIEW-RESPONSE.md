## 0. 本轮方法与事实基础

第一轮把"能力有对应实现"补成了"默认路径真的生效"（F1/F2/F13 三个 P0）。
本轮换了一个更狠的验证方式：**不看代码宣称什么，直接构造运行时探针**。
结果在 v0.7.2 里又抓到 20 项缺陷，其中 3 项是 P0——它们都符合同一个模式：

> 机制写对了，但输入边界没守住 → 静默失效或可被普通命令绕过。

| 复核动作 | 结果 |
| --- | --- |
| 运行时探针（本轮新增） | 复现 `tune` 关掉隔离红线、restore 路径穿越、NaN 绕过弃权、短 id 静默 no-op 等 |
| 逐模块审读 | `service.ts` / `store.ts` / `recall.ts` / `text.ts` / `security.ts` / `appraisal.ts` / `episode.ts` / `frames.ts` / `commands.ts` / `vault-tools.*` |

| 指标复跑 | 8 项合成门槛、bench-real 13/13、10k 规模、验证层 11/11，逐项未退化 |

## 1. 研究依据（为什么先修边界、再补功能）

### 1.1 工作区三份研究文档给出的硬约束

| 来源 | 结论 | 本轮落点 |
| --- | --- | --- |
| 《人类大脑记忆功能的具体表现与原理》 | Bartlett：记忆是**建构性重构**；Loftus 只改提问动词就能衍生不存在的细节；DRM 让被试自信误认未出现的词 | 检索系统必须把"我不知道"留在输出空间里。S3 修的正是 `verdict='hit'` 被 NaN 绕过——这比"答不出"危险得多，是**带着假证据的自信作答** |
| 同上 | 情景记忆易受干扰、语义记忆较稳定；艾宾浩斯先快后慢；NREM/REM 双相巩固 | 强项，刻意不动：五档 tier、七因子保留度、`decayState` 单一入口、双相巩固全部逐位兼容 |
| 《AI 意识与情感的神经基础与工程路径》 | Barrett 建构论四步（身体变化→感知→结合经验解释→情绪出现）；内感受是真实计算量；获取意识 ≠ 现象意识 | 本轮只修**感知层输入质量**（第二套词表的词边界、"特别"里的"别"），不改状态机与边界声明，不输出"我感到…" |
| 《MnemoVault-DSH 记忆与情感插件开发文档》 | 端口/宿主契约、配置由宿主 schema 解析 | S1 的根因正是"宿主会解析"这个假设在运行时命令路径不成立；修复遵守既有契约：红线只在部署配置里设定 |

### 1.2 同类项目与公开基准的对照（引自评判报告 §12/§16/§19）

- 报告第 19 节把 **C3 公开基准、C4 基线对照、C6 第三方红队、C7 私有集**列为 P0，
  并指出"没有它们，前三件事的收益都无法证明"。本轮能补的是**评测基础设施与机制覆盖**
  （验证层 8 → 11 节、每个新能力都有 CI 硬断言），补不了外部数据与外部执行者。
- 数据可携带（E6）、删除权（E2）、访问审计（E10）在同类产品里是运维标配。
  本轮的 U4/U5 补的是"HELP 承诺了却没实现"与"校验只做了一半"这两类
  **产品化最后一公里**问题，而不是再加一个新概念。
- Mem0/Zep/Letta 的公开形态普遍把多租户边界放在服务端。S1 的修复正是把
  "边界可以被一条命令改写"这个后门关掉——这是 §14/§15 的前置条件，不是锦上添花。

### 1.3 本轮的取舍原则

1. **先修可被普通输入触发的静默失效**（S1–S14），再补功能（U1–U5）。
   一个能被 `tune` 关掉隔离的导出工具，功能越多风险越大。
2. **不改排序主链**。A9 rerank / A10 迭代检索会改动 `hits[0]`，
   直接冲击 Recall@8 / MRR / trap=1.00 等既有硬门槛；本轮继续留到下一版，
   不为了"看起来做了"而引入回归。
3. **强项逐位保持**：确定性写入、内容寻址、双时态版本链、衰减统一、
   `verdict` 语义、MC03 布局全部未动；所有既有指标复跑一致。

## 3. 本轮实测抓到、上一轮未发现的缺陷（摘要）

| 编号 | 缺陷 | 触发方式 | 后果 |
| --- | --- | --- | --- |
| S1 | `tune` 可改写安全配置 | `/mnemo tune security.allowGlobalScope=true` | 隔离红线被关，跨租户可见 |
| S2 | restore 路径穿越 | manifest `name: "blob/../../x"` | 覆盖目标机任意文件 |
| S3 | NaN 绕过弃权 | 证据/归一化里混入 NaN | 陷阱题 `verdict='hit'`，自信答错 |
| S4 | `[].every()` 恒 true | 无来源映射的 cell | expand 永远拿不到原文 |
| S5–S9 | 五处短 id 各自 padStart/padEnd | 4 位短 id | 静默 no-op 删除、边指错对象、解释错记忆、误删他人快照 |
| S8 | clearLattice 无事务 + 全删边 | rebuild 保留 kind 3/4/5 | 半清空库、关系图丢失、`NOT IN (NaN)` |
| S13 | 快照 id 截到 64 位弱尾段 | 渲染文本碰撞 | `ON CONFLICT DO NOTHING` 静默丢新快照，重放取回错误文本 |
| S14 | 第二套情感词表无词界 | `I am unhappy` | `goalCon=+0.333`，判成正向 |

全部 20 项都有 `test/v073-fixes.test.mjs` 或 `scripts/bench-verify.mjs` 里的
"改回旧代码就变红"断言。
