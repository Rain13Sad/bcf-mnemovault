# v0.6.0 — LLM 层面的情感记忆引擎

> 发布日 2026-11-01 · 基线 v0.5.2（`1f50af2`）· 11 个 npm 包 · 227 测试
> 完整方案：[`docs/design/V0.6-PLAN.md`](../design/V0.6-PLAN.md)

## 一句话

0.5.2 让它在真实规模上站得住；**0.6.0 让它离开宿主也活着**。

## 为什么这次是"决策层"的更新

v0.5 之前，这个项目的身份是"一个 DSH 插件"：能力都长在 Cordis 钩子上，
换一个宿主等于把接线重写一遍。"适配常用大模型"这句话在那种结构里没有意义——
因为能接几家，取决于你愿意抄几遍胶水。

v0.6 把它拆成三层：

```
core   同步内核，零第三方依赖      ← 只认端口
llm    新增：HTTP → 端口          ← 只认宿主
host   DSH / MCP / 你的 Agent     ← 只认引擎
```

于是"支持一家新模型"从**写代码**变成**填一行数据**（`MODEL_PROFILES`）。
这次更新里最重要的一行代码不是某个算法，而是这张表。

## 你会看到什么

### 1. 新包 `@rain13sad/dsh-mnemo-llm`

6 家 provider / 11 个模型画像：DeepSeek · OpenAI · Anthropic · Google · Ollama · OpenAI 兼容。
只用内置 `fetch`，**零第三方依赖的承诺仍然成立**。

两个开关默认关：`embeddingEnabled` 与 `extractEnabled`。打开会打破"离线可跑"，
这个交换由你决定。

### 2. 情感记忆的四条机制（每条都有断言）

| 机制 | 你会在行为上看到什么 |
| :--- | :--- |
| 评价 → PAD | 同一句话在不同关系阶段得到不同心境，不是固定标签 |
| 心境一致性 | 难过时更容易想起难过的事——**但负向侧打 0.7 折**，不让它变成反刍 |
| 唤醒倒 U | 中等激动记得最牢；极度激动反而碎片化（不会把争吵写成里程碑） |
| 情感摘要 | 进 prompt 的那一行 `A\|mood:…` 约 30 token，**字节稳定**（不破坏 prefix cache） |

### 3. 跨模型上下文编译器

同一批记忆，给 GPT-4o 和给本地 7B 模型长得不一样：

- 弱模型自动降散文（它看不懂 MRS 行式，硬给就是白花 2.5× token）
- 超预算先换列式，再丢条目
- 超价格上限继续裁——**闸门用钱表达**，因为"每轮不超过 ¥0.0003"是采购听得懂的话

### 4. 面板：记忆星图 + 调控台

- **星图**：64 维向量用固定种子随机投影到 3D。新记忆只增加点，**绝不移动旧点**
  （PCA 会让整张图随新数据旋转，用户以为记忆被改了）。
- **调控台**：16 个旋钮，每个在应用之前就显示它对 token/轮 与成本的影响。

## 坏消息（按项目规矩先说）

**MRR 0.681 → 0.650。** Recall@8 仍是 0.941。

原因是 D5 的修复：`embStoreDim` 现在来自 schema（64），而不是第二张手写的默认值表（128）。
64 才是盘上真实库用的维度，所以 0.650 是**真数字**，0.681 是量在一个从没发布过的维度上。

换来的：存储比 0.839 → **0.769**，单条 cell 341 B → **277 B**，
以及"照着 README 写代码打不开自己的库"这个缺陷消失。

## 修复

| # | 问题 | 现在 |
| :-- | :--- | :--- |
| D1 | 全新机器上 core 起不来（`unable to open database file`，症状甩给下游 6 层） | `open()` 自己建父目录 |
| D5 | `embStoreDim` 两张默认值表，而它参与布局键 | 只有一个来源：schema |
| D6 | `dsh.client.inject` 里有个宿主不存在的包（哑弹） | 删掉 |
| D2 | 照 README 装会解析到坏版本（pnpm 11 的 `minimumReleaseAge`） | 主命令钉版本 |
| D3 | 桌面 profile 必须先由应用初始化 | 文档写成三步 + 排障口令 |
| N1 | 只提交 `recall.ignition` 会把整个 recall 段写空 | 点号路径 + 一层深合并 |

v0.5.3 的现场报告（`v0.5.3-desktop-install-report.md`）里那四条代码缺陷，本版**重新实现**了
D1 / D5 / D6，并保留了 `paths.ts`——丢掉它们等于把已知的 P1 缺陷重新引进来。

## 升级注意

- **存储布局不变（MC03）**，旧库不需要 rebuild。
- `embStoreDim` 的默认值从 128 变成 **64**：如果你此前用 `defaultConfig()` 建过库，
  那个库的布局键是 `…:128:3`，升级后需要 `/mnemo rebuild --from-log`。
  宿主建的库一直是 64，不受影响。
- 新增的 `llm` 配置段全部有默认值，不配置也能跑（走哈希 + 规则）。
- 面板新增两个页签；旧快照缺字段时会降级渲染。
