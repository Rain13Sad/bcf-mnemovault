# v0.5.1 — 修掉符号、振荡与死开关

0.5.0 让决策链会动了。这一版修它暴露出来的问题，外加一个从 0.2 就在、
因为**所有测试都用正数**而一直没人发现的编码 bug。

---

## 一、符号在 i8 边界上丢了（P0）

```
buf[0x2c] = q8(-0.54)   →  -68
Uint8Array[0x2c] = -68  →  188      ← 回绕
decode: 188 / 127       →  +1.48    ← 符号没了
```

后果不是"少一点点精度"：**所有负的 `valence` / `arousal` / `dominance` 读回来都是正数**。
一条 -0.54 的难过记忆变成 +1.48，下游 `clamp01(|v|)` 再把它钉死在 1.0，
七因子里的 `affect` 项从此失去分辨率——"情绪强度"永远等于 1。

修法：写入 `& 0xff`，解码 `((b << 24) >> 24) / 127`。
**不需要 rebuild**：字节一直是补码，错的是读取端。

> 为什么三年没被发现：`test/core.test.mjs` 的往返测试用的是 `valence: 0.6`。
> 现在补了一条专门跑负值的往返测试。

## 二、周年加成破坏单调性（P0）

v0.5 的写法是 `score = base × stale + anniversary`：

1. 加在陈旧包络**之后**——包络把分数压到 0.085，+0.25 还能把它抬到 0.336；
2. 幅度（0.25）大于档宽（约 0.18），天然能跨一到两级；
3. 不区分"该降"还是"该升"。

实测：**已压实的墓碑在第 4 个周年被 `demoteDue` 自动抬回 tier 3**，而它的残差早已永久释放——
等于把"墓碑"这道单向门反向打开，还复活了一条检索层拿不到、原文也回不来的记录。

现在：周年只对"有效且非墓碑"生效，乘上包络，抬升上限是**本档上沿**，绝不跨档。

## 三、`demoteDue` 会升档（P1）

`nextTier` 是双向的，而降档 pass 里没有任何一处限制方向。纯时间推进就能把记忆重新烫热：

```
+200 天: tier 1 → 2  降
+365 天: tier 2 → 1  升   ← 没有任何提取、没有任何重放
```

现在降档 pass **只降不升**；升档交给真正的使用信号：强命中召回（`score ≥ 0.55`）或巩固期睡眠重放。

## 四、`includeTombstones` 是死开关（P0）

压实把 `emb` 与 `residual` 都丢了，于是语义路 `cosine(null, …) = 0`；符号路又只吃实体 SDR。
开关开不开都召不回——**一条墓碑如果忘了 id，就再没有任何检索路径能发现它**。
它不是"已删除"（id / digest / 槽位都在），但它是**不可发现的**。

新增一条"目录通道"：query 分词（拉丁词 + 中文单字，过滤停用字）与 `digest` 求覆盖率，
`hit ≥ 2 且 cover ≥ 0.3` 才入选，得分封顶 0.85，只在 `includeTombstones` 时启用。
`memory_recall` 工具也加了 `include_tombstones`——此前只有面板的「复活」按钮能触达墓碑。

## 五、测试时钟不传导（P2）

`createHarness({ now })` 只喂给了事件时间戳，`MemoryService` 仍读 `Date.now()`。
于是"把时钟推到 1000 天后"的测试**静默失效**：`demoteDue` 看到的 `now - tAccess` 依然接近 0，
直接按"刚访问过"跳过。新增 `MemoryService.setClock()`，harness 接上，并断言
`h.now() === memory.nowMs()`。

## 六、测试从"采样"改成"扫描"

v0.5 的 16 条测试测了第 400 天和第 900 天——恰好绕过 365 / 730 两个周年窗口，
所以上面三个缺陷一条都没被抓住。新增的三条性质：

```text
性质 1（单调）  时钟推 10 年、每 7 天一步：tier 只能变冷
性质 2（可达）  必须到达 tier 4，且此后不回退
性质 3（不变量）tInvalid 超过宽限期 ⇒ 恒为 P2，与周年/陈旧无关
```

## 七、面板

- 「保留度」页加筛选与排序：按摘要过滤、按档位分段筛选、按分数/档位切换排序。
- 无障碍：`aria-current` / `role=tab` / `role=status` / `:focus-visible` 焦点环。
- 细节：选中项左侧指示条、`scrollbar-gutter: stable`（切页签不左右跳 8px）、
  toast 补定位上下文（此前可能跑到宿主页面角落）、`prefers-reduced-motion` 下关闭过渡。

## 八、文档：把"手写死的数字"变成会失败的断言

外部评审把五份 README 逐条核对，发现**同一个事实最多有四个值**（规模 4 套、Node 4 个、
测试数 3 个、缺点条数 4 个），还有一句"零运行时依赖"与 8 个包里的
`import z from '@deepseek-ai/schemastery'` 直接矛盾。

根因不是写错，是**手维护**。新增 `scripts/check-readme.mjs` 并接进 `npm run verify` 与 CI：

- 五份都要有 `DOC-VERSION`（等于 package.json）、H1、统一 Node 版本、依赖口径、代码块语言；
- 英中两份还要校验源文件数、行数（±2%）、测试数、缺点条数（对齐 PROJECT-GUIDE 的 D1–D19）、
  存储比的两个适用区间。

同时把 README 本身重写：补 H1 与可运行的 API 示例（此前 23 个代码块里 0 行 TypeScript）、
中文补目录、目录树补上 `retention.ts` 等 7 个漏掉的文件、英文限制清单重排并补回缺的三条、
日/韩/西改成"摘要 + 指针"并声明自己是摘要。

## 十、兼容性

- **存储布局不变**（MC03），旧库不需要 rebuild。
- **符号修复会让旧的负效价"变回负数"**——这是正确值，不是数据被改写。面板上原来显示为正效价的
  难过记忆，升级后会显示为负效价。
- 升级后第一次 `demoteDue` 可能比 0.5.0 多移动一些条目：0.5.0 因为周年加成把它们挡在了上面。
