# v0.5.3 — 让"能装上"这件事成立

> 发布日期：2026-10-31 · 基线 DSH `0.2.1-rc.3` · 存储布局 MC03（**旧库不需要 rebuild**）· 无 API 破坏性变更

0.5.0 让决策链会算，0.5.1 让它算对，0.5.2 让它在真实规模上站得住。
0.5.3 修的是更前面的一件事：**它根本没装上。**

0.5.2 已经发到 npm，CI 全绿，176 条测试通过。而它十个包里有四个**装不进 DSH**。
这四个缺陷没有一个落在业务逻辑里——它们全部落在"代码是对的"和"宿主接受它"之间的缝隙，
而那正是当时没有任何测试在看的地方。

---

## 一、四个静默失败

| 症状 | 真实原因 | 为什么会一直没人发现 |
| :--- | :--- | :--- |
| 插件管理器拒绝安装 `ui`：**「这个包没有声明组合包，不能作为插件管理」** | 包声明了 `dsh.client`，却没有 `dsh.bundle` | 它的 `lib/index.js` 只导出几个常量，没被当成"组合包"看 |
| 装上 `proactive` / `devkit` 后**一行都没加载** | 两个包声明了 `dsh.bundle.patch`，指向的文件**不存在**；Loader 读到 ENOENT 就跳过整层 | `files[]` 里写着这个路径，发布包是"完整"的 |
| `core` 安装到最后一步被**整体回滚** | patch 里用了 `!!js` 模板表达式；安装期的 YAML 解析器不带自定义标签 | 启动期的 Loader 支持 `!!js`，所以"本地能跑" |
| 记忆库被写进名字叫 `~` 或 `undefined` 的目录 | `~` 从来没被展开；`ctx.baseDir` 在 Loader 上并不存在（它叫 `baseUrl`） | 不报错，只是写错地方 |
| 面板在宿主里**从来没出现过** | `exports["./client"]` 指向的 `lib/client.js` 从未被生成；且宿主只伺服单个文件、格式必须是 `window.__ModuleLoader__.load({...})` | 预览、SSR 测试、bundle 测试都直接 import `lib/client/Panel.js`，走的是另一条路 |

最后一条是这一版最值得记的一件事：**面板此前只在 `npm run panel` 的预览里存在过。**
预览链路是把编译后的 ESM 逐个用 HTTP 伺服、再把 `react` 重写成 shim；
宿主链路是伺服**一个** `client.js`，它必须调用 `__ModuleLoader__.load()` 并从 `require` 形状的模块表里取 react。
两套契约，其中一套从没被测过。

## 二、改了什么

### 1. `ui` 变成一个真正的组合包

`packages/ui/src/index.ts` 现在是合法的 Cordis 插件（`name` / `inject` / `apply`）。
host 侧**空转**——它存在的唯一目的是让 Loader 树里有一行带 `dsh.client` 的条目，
因为浏览器名单是扫描这棵树得到的：没有行，`client.js` 一次也不会被请求。

顺带把 host 半的 `import` 全部去掉：以前它会 `export { MnemoPanel }`，
等于把 react 与整个面板拖进 host 进程。

### 2. `devkit` 不再假装是插件

它是无宿主运行器（`createHarness`），不是 Cordis 插件。删掉 `dsh.bundle` 与 `cordis.patch.yml`。
README 里把它单列为"不是组合包"。

### 3. patch 里不再出现 `!!js`

`core` 的 patch 现在只写字面量。依赖宿主上下文的默认值（库路径）改到 `apply()` 里解析：

```ts
// packages/core/src/paths.ts
export function resolveVaultPath(p, baseUrl?, home = homedir()): string
```

解析顺序：`:memory:` 原样 → `~` 展开 → 绝对路径原样 → 相对路径按 profile 目录（`ctx.baseUrl`）。

### 4. client 入口真的生成了

新增 `scripts/client-build.mjs`，在 `npm run build` 里紧跟 tsc 之后执行，
把 `lib/client/**` 折成一个 `lib/client.js`：

```js
window.__ModuleLoader__.load({
  id: "@rain13sad/dsh-mnemo-ui",
  factory: (require) => { /* 17 个模块的内部注册表 */ return module.exports }
})
```

**为什么不用 esbuild**：v0.4 把它删掉是有理由的——它带平台限定的 optionalDependency，
lockfile 只锁当前平台，npm ≥11 在别的平台 `npm ci` 直接失败（`ci-check-publish.mjs` 第 ④ 条门禁）。
为一个 140 KB 的 bundle 把发布矩阵弄崩不值得。

转换器只处理 tsc 的产物形态（全部单行、只有具名导入、没有 default / namespace / `export *`），
遇到不认识的形态**直接让构建失败**——宁可红，也不要产出一个在浏览器里静默半死的 bundle。

### 5. 面板：降级要说出来

数据源不是宿主 remote 面时，第一屏出现一条提示，区分三种情况并给出下一步：

- 演示数据（不落库）
- 只读事件流（装了 core 但没装 tools）
- 未连接记忆库（core/tools 都不在同一个 profile 里）

以前这三种情况长得一模一样：一屏的 0。

## 三、新增门禁

### `npm run check:manifests`

检查的是**清单与磁盘的一致性**，不是代码行为：

1. 版本与根一致；兄弟包依赖是 `^<version>`
2. `dsh.bundle.patch` 指向的文件存在，且在 `files` 白名单里
3. 声明 `dsh.bundle` 的包，`lib/index.js` 必须导出 `apply` 函数与 `name`
4. patch 里插入的每个包名，必须是本包或本包的依赖
5. patch 里不得有 `!!js`、不得有制表符
6. 声明 `dsh.client` 的包必须有 `lib/client.js` 且被 `files` 覆盖
7. 两个包不得插入同一个行 id（加载期会出现重复行）

已接进 `npm run verify` 与两条 CI job。

### 两个测试

- `test/client-bundle.test.mjs`：用只提供 `window.__ModuleLoader__` 与 `require` 的假内核
  执行真的 `lib/client.js`，断言 `apply` 注册了 `main` 与 `sidebar.panellist` 两个槽，
  且 disposer 都交给了 `ctx.effect`。
- `test/paths.test.mjs`：`~` 展开、`:memory:` 透传、`baseDir`/`baseUrl` 那个坑。

测试数 176 → **184**。

## 四、安装（端到端验证过）

```bash
dsh plugin add \
  @rain13sad/dsh-mnemo-core @rain13sad/dsh-mnemo-affect @rain13sad/dsh-mnemo-encoder \
  @rain13sad/dsh-mnemo-recall @rain13sad/dsh-mnemo-consolidator @rain13sad/dsh-mnemo-proactive \
  @rain13sad/dsh-mnemo-tools @rain13sad/dsh-mnemo-settings @rain13sad/dsh-mnemo-ui
```

验证方式（在本机 rc.3 上跑过）：

```bash
# 1. 九个包都成为 profile 的直接依赖 → reconciliation 全部启用
node -e "console.log(require('$DSH_HOME/profiles/<名字>/package.json').dsh.profile.bundles)"

# 2. 九行都真的 compose 出来了，且没有 skipping / warning
dsh --profile <名字> --dump-config | grep mnemo
```

`ui` 额外依赖 `tools`（`^0.5.3`）：只装面板会顺带拉进 `tools → core + affect`，
因为一个背后没有库的面板不算功能。

## 五、兼容性

- **存储布局不变**（MC03），旧库不需要 `rebuild`。
- **配置项不变**，但 `dbPath` / `residualDir` 的**语义变清楚了**：以前 patch 里写
  `!!js ${ctx.baseDir}/…` 会得到 `undefined/…`，现在不写就用 `~/.dsh/mnemo/…`。
  如果你的库正好在 `undefined/mnemo/` 下，把它挪到 `~/.dsh/mnemo/` 即可（或在 patch 里写绝对路径）。
- **`dsh-mnemo-ui` 的 `lib/index.js` 不再导出 `MnemoPanel` / `PanelProps`**：
  host 半不该把面板组件带进 node 进程。需要组件请从 `@rain13sad/dsh-mnemo-ui/client` 取。
- `devkit` 不再是组合包：`dsh plugin add @rain13sad/dsh-mnemo-devkit` 现在只会装成一个普通依赖（这是对的）。
