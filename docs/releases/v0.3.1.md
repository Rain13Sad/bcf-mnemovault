# v0.3.1 — 先让这一版能用，再补安全与正确性

v0.3.0 在技术上是进步的（存储比首次降到 1.0 以下），但它**装不上**：
`npm ci` 直接失败，`npm install` 后编译报错。10 个包的 `version` 升到了 0.3.0，
而 8 个 `package.json` 里对兄弟包的依赖还写着 `^0.2.0` —— semver 里 `^0.2.0` 不含 0.3.0。
一个 8 处字符串的问题让整个版本不可用，说明缺的不是能力，是**门禁**。

这一版先把它修好，再逐条处理两次外部审查指出的问题。

## 修了什么

### 发布工程

- 兄弟依赖 `^0.2.0` → `^0.3.1`，重新生成 `package-lock.json`
- 新增 `scripts/ci-check-publish.mjs`：版本一致 / 兄弟依赖范围 / lockfile 同步，三项不一致就失败；
  已接进 CI 与 `npm run publish:all`
- 新增 `scripts/publish-all.mjs`：按**依赖顺序**发 10 个包（先 core 后 ui），遇到 2FA 错误立即停
- `engines.node` `>=22.5` → `>=22.13`（22.5–22.12 的 `node:sqlite` 需要 `--experimental-sqlite`）
- 在干净目录实测 `npm ci && npm run build && npm test`：10 包全构建、115 条测试全过

### 安全（两条 P0，连续两版未修）

- **PII 脱敏贯穿全部派生字段**。`buildCell` 里的实体抽取、槽位填充、向量、话题指纹
  原来读的都是**原文**，只有 `digest` 用了脱敏文本 —— 于是"摘要里是 «SECRET:1»、
  旁边的槽位里是完整手机号"，而槽位会经 `kvPairs()` 直接渲染进模型上下文。
  现在从入口起只用脱敏文本，槽位出口还有一道 `scrubSlots()` 兜底。
- **PII 规则 7 类 → 11 类**：补 IPv4、银行卡（Luhn 校验，避免误伤订单号）、
  PEM 私钥块、Bearer token、URL query token。
- **影子日志也脱敏**：`session_log` 是重建依据，重建用的编码器读脱敏文本，所以存脱敏版本等价。
- **`forget(hard)` 真删残差**：新增 `releaseResidualRef()`，按 sha 检查是否还有 cell 引用
  （残差按轮共享，不能用 `ref_cnt` 判断），没有则物理删除。`doctor` 报告并清理孤儿残差。
  **GDPR 删除权在这条路径上才真正成立。**
- **`memory_forget` 走审批**：物理删除永远要审批，没有审批面时直接拒绝；
  `mnemo_command` 工具通道禁止 `forget --hard`（模型能自己发 `--yes`）。
- **egress 守卫改 fail-closed**：白名单之外一律扫（含不认识的工具名）。
  旧正则只认下划线分词，`webSearch` / `WebSearch` / `execute_shell` / `write_file` / `send_email` 全部漏过。
- **去掉 UI 的 XSS 面**：解释器渲染不再用 `dangerouslySetInnerHTML`，改为构造 React 节点。

### 正确性

- **只读接口不再有写副作用**：`snapshot()` 里调 `blockedBy()` 会顺手把 `todayCount` 清零 ——
  **用户打开面板看一眼，当日配额就没了**。现在跨日滚动只在 `fire()` / `tick()` 里发生。
- **主动开口状态落盘**：重启不再清零（之前重启即绕过每日上限与静音）。
- `dayKey` 改本地日期；`tick` 门槛 0.45 → 0.3（`pickMemory` 0.42 之前永远走不到，是死路径）；
  边界词静音落地（头注释承诺过但没实现）。
- **打分 `moodW` 双重加权**：`wAffect × moodW² × congruence` → 只在 weights 里乘一次，
  面板上"0.62 × 1.00"与实际贡献重新对得上。
- **写入 `seq` 差一**：cellId 与 `cell_sources` 用的不是同一个值，从日志重放会算出不同 cellId。
- **三处 `Math.random` 改确定性**（REM 联想采样、`queryId`、主动开口挑记忆）。
- **边改存完整 64 位 `dst`**：32 位前缀在 10 万 cell 下期望碰撞 ≈1.2 对，且每条边一次全表扫描。
- **`runRecall` 返回真实 `snapshotId`**（内容寻址，与 service 同源）。
- **英文句号切分**：`I use pnpm. I like dark mode.` 之前会粘成一条命题。

### 性能

审查实测指出"99.9% 的耗时不在 Jaccard，而在存储层"：

- prepared statement 缓存（38 处 `prepare()` 全部无缓存）
- `forEachCell` 单查询 + `.iterate()` 流式（之前是 N+1 条 SQL）
- `getCell` 合并为单趟 SQL
- `PRAGMA busy_timeout = 5000`
- 面板快照节流：之前**每次召回**都同步重建整份快照（全量 cell 视图 + doctor 两次全扫 + 标签 + 分类）

实测（本机，真实 SQLite 路径）：500 cell 召回 p50 **90 ms → 26 ms**，1000 cell 43 ms，
`forEachCell` 2000 cell **111 ms → 34 ms**。

诚实说明：**写入仍是 O(n)**（去重 + 冲突检测各一次全扫），这一版只削了常数因子。

### 面板

统一四档字号与 4 的倍数间距、暗色模式重新取色（不是反色）、去掉重投影、页签胶囊高亮、
小节标题加 3px 强调条、焦点环与滚动条；标签云改为只取 PATIENT / MANNER / QTY 槽位
（之前从 digest 抓 2–6 字片段，产出「别写进代码」这种分词失败的半截话）；
窄侧栏（≤340px）单独一档布局。
