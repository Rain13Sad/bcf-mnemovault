## 0. 文档信息与变更记录

### 0.1 这一版做了什么

v0.1 的问题不是"写得不够多"，而是**有三个地方算错了，还有两个地方逻辑上说不通**。这一版的首要任务是把这些算清楚，而不是加功能。

| 类别 | 数量 | 处置 |
| :--- | ---: | :--- |
| 致命缺陷（会让方案根本不工作） | 2 | 重写数学，改默认参数 |
| 严重缺陷（绑定层连锁错误） | 1（含 3 个子项） | 换绑定方式 |
| 逻辑矛盾（前后不一致） | 5 | 统一口径，删除错误断言 |
| 工程疏漏（能跑但会出事） | 5 | 补机制 |
| 版本适配（0.2.1-rc.3 破坏性变更） | 6 | 逐条对齐 |
| 新增能力（可操作性） | — | 新增第 12、13 章 |

> **这一版的缺陷不是读出来的，是跑出来的。** 前三个缺陷由 `mnemo-sdr-check.mjs` 的实测暴露——写文档时它们看起来都自洽。这也是本文反复强调"性能数字必须回填实测"的原因。

### 0.2 一句话结论

> **v0.1 的架构是对的，数学是错的。** 稀疏码套用了密集码的算子（多数表决、汉明相似度、XOR 绑定），这在 D=1024、密度 2% 下会让记忆库直接失效——实测结果是全零向量、相似度恒为 0.99、解绑准确率 0。v0.2 换成集合语义（并集叠加 + Jaccard + 角色置换绑定），并把维度提到 2048、稀疏度降到 0.39%，容量与信噪比才立得住。

## 1. v0.1 复审：13 处缺陷与修复

这一章是本文最有价值的部分——它记录了一个看起来自洽的设计在数学上如何崩掉。

### 1.1 两处致命缺陷 + 一处连锁错误

#### D-01　稀疏码 + 多数表决 = 空向量

**v0.1 写法**：`bundle(xs) = majority(xs)`，每个 SDR 密度 2%（1024 位中约 20 位为 1）。

**为什么错**：多数表决要求每个 bit 的"1 的概率"接近 0.5。当 p=0.02、n=20 时，单个 bit 上"1"的期望个数是 0.4，要过半（>10）的概率在 10⁻¹² 量级。**结果不是"稍有噪声"，而是 bundle 恒等于全零向量。** 所有命题的 SDR 都变成 0，`sim` 恒为 1，检索彻底失效。

**修复**：稀疏码的叠加语义是**集合并集**，不是多数表决。

```
bundle(xs) = ⋃ xs            // 位或
若 density(bundle) > cap:     // cap = 12%
    bundle = kWTA(bundle, cap·D)   // 保留激活最强的位，按哈希决定平手
```

并集保留每个成分的全部位，因此"用其中一个成分去查"能精确命中（overlap = k），噪声底只有 k²/D。这是稀疏 VSA 的标准做法。

#### D-02　稀疏码 + 汉明相似度 = 所有东西都 99% 相似

**v0.1 写法**：`sim(a,b) = 1 − popcount(a⊕b)/D`。

**为什么错**：D=1024、k=20 的两个**完全无关**的稀疏码，汉明距离约 40 位，`sim = 1 − 40/1024 = 0.961`。也就是说"用户喜欢深色模式"和"服务器在杭州"的相似度是 0.96。所有阈值（0.95 合并、0.80 关联）全部失效，整个去重与冲突检测逻辑坍缩成"全部合并"。

**修复**：稀疏码用 **Jaccard**。

```
sim(a,b) = |a∩b| / |a∪b|        // 无关码期望 ≈ k/(2D−k) ≈ 0.002
```

同时把 `identity()` 的位数从硬编码 20 改为参数 `k`，与 D 解耦。

#### 连带修复：绑定层与容量层的连锁错误（D-03）

v0.1 的 SDR 层不止前面两个错，还有三处连在一起的问题。它们单独看都不致命，叠在一起会让"解绑查询"彻底不可用。

**(a) XOR-置换绑定让密度翻倍。** v0.1 写 `bind(a,b) = a ⊕ ρ(b)`，注释说"密度保持"。这是错的：XOR 是**对称差**，两个 k=8 的稀疏码若无重叠，结果就是 16 位。实测 `popcount(bind(a,b)) = 16`，不是 8。后果是叠加 24 项时密度冲到 18.75%，被 kWTA 截断到 12%，成分的位被裁掉，解绑全部失败（实测 rank-1 准确率 0/24）。

**(b) 容量归属搞混。** v0.1 说"单 cell 绑定项 ≤ 24"——把**绑定**的容量和**叠加**的容量混为一谈。绑定只是换坐标，本身不产生容量上限；有上限的是叠加，而且上限取决于**每项占多少位**。绑定若让每项从 8 位涨到 16 位，容量直接砍半。

**(c) 置换表种子塌缩。** 用 `key[0] ^ key[1]` 作为置换表种子时，k=8 的稀疏码有 78% 的概率前两个字全为零——**所有角色的置换表变成同一张**，角色区分消失（实测 rank-1 准确率 4/24，且"正确"与"错误"成分得分完全相同）。必须哈希整码。

**修复后的绑定**：不用 XOR，用**角色置换**。

```
bind(filler, role) = permute(filler, Π_role)      // Π_role 由 role 码全哈希生成
unbind(x, role)    = permuteInv(x, Π_role)
```

密度精确保持（8 位进、8 位出），可逆性精确成立，角色之间因置换表不同而正交。这是稀疏 VSA 里"置换绑定"的标准做法，比 XOR 更适合低密度码。

**修正后的容量表**（D=2048, k=8，数值来自实测脚本 `mnemo-sdr-check.mjs`）：

| 量 | 公式 | 实测值 |
| :--- | :--- | :--- |
| 无关单码 Jaccard | k/(2D−k) | 0.000 |
| 无关 bundle(24) Jaccard | ≈ 2·(nk/D)/(1+nk/D) | 0.047 |
| bundle 项数上限（密度 12%） | cap·D/k | 30（实测密度 11.4%） |
| **工程建议上限** | 实测 rank-1 全对 | **24** |
| n=24 时正确/错误成分区分度 | — | 2.7× |
| n=30 时区分度 | — | 1.6×（开始退化） |

> 注意"区分度"只有 2.7×，不是数量级差距。这意味着**解绑检索必须用 argmax（排序取第一），不能用绝对阈值**。v0.1 里"sim > 0.5 就算命中"的写法在新方案下永不成立——绝对阈值是密集码时代的习惯，稀疏码里 sim 的绝对值本身就没有可比性，只有相对排序有意义。这条约束贯穿 §7.5 的去重与 §9.2 的打分。

## 2. 问题定义：为什么文字不能当记忆

### 2.1 现状的四笔账

当前主流方案把记忆做成"文本块 + 向量索引 + RAG 拼接"。它能在 demo 里工作，但四笔账始终算不平。

**Token 账。** 一条"用户偏好深色界面"的记忆，原文可能埋在 300 字的产品讨论里。RAG 把整块 300 字塞回上下文，真正有用的信息是 6 个字。上下文窗口从 100 万涨到 1000 万也治不了——浪费率是结构性的，不是容量问题。DSH 的 compaction 能把旧对话摘要成 500 token，但它压缩的是**对话**，不是**知识**：同一件事在十次对话里被摘要十次，重复十次。

**推理账。** 文本记忆要参与推理，必须先被模型重新解析成结构。模型每读一次"用户上周说不喜欢红色，但这周又说红色不错"，就要重新做一次矛盾检测。这个检测本该在写入时做一次，而不是在读取时做一万次。

**检索账。** 单一向量通道对"精确事实"和"模糊联想"用同一把尺子。问"API key 存在哪个文件"要的是符号精确匹配；问"上次那个思路还能怎么改"要的是发散游走。一个余弦相似度同时服务两者，两边都不准。

**演化账。** 文本记忆是静态的。人对同一件事的记忆强度随时间和情绪变化，AI 的记忆不会——要么在，要么被删。于是"记忆"退化成"数据库"。

### 2.2 本文的立场

> **记忆不该是文字。文字是给人看的投影，不是给机器存的格式。**

文字是**表面**，不是**基底**。人脑里也没有文字：海马存索引与绑定关系，皮层存分布式表征，杏仁核给表征打情绪权重。文字只在"说出来"那一刻被临时组装——这正是要复刻的分工：

```
基底（不花 token）        投影（花 token）
─────────────────       ─────────────────
结构化晶格 + 稀疏码   →   每轮约 180 token 的记忆卡片
+ 超图关系 + 情感向量      （需要细节时再按需展开）
+ 无损残差（可回溯原文）
```

三条不可让渡的公理：

| 公理 | 表述 | 工程后果 |
| :--- | :--- | :--- |
| **A1 双层无损** | 存储层字节级无损；表面层语义级有损但可回溯 | 磁盘便宜、token 贵。省 token 不能靠丢信息，只能靠"先摘要、细节按需取" |
| **A2 写入时计算** | 能预计算的（矛盾、去重、抽象、情绪权重）都在写入时算完 | 读路径只做排序与打包，p95 延迟可控 |
| **A3 情感是参数不是台词** | 情感是影响检索、采样、工具阈值的数值状态，不是输出里的形容词 | 可测量、可回放、可回归测试 |

### 2.3 与 DSH 原生记忆观的关系

DSH 的立场是"日志即记忆，上下文是投影"：`SessionEvent[]` 是唯一事实源，`deriveMessages()` 派生模型可见历史，铁律是 **model-visible means logged**。跨会话语义记忆是当前版本的明确空白，官方把这块留给插件生态。

MnemoVault 的定位：

- **不替换** Session Log，而是在日志之上加一层**可再生的派生物**。每个 cell 携带 `sourceSeqs`，晶格损坏 = 重建，不是数据丢失。
- **不绕过** surface。每次注入都必须写 `memory/recall` 事件，且事件内含渲染快照（见 D-05）。
- **不侵入** agent loop。所有能力以 Service + Hook 挂载，`ctx.effect()` 保证可卸载、可热重载。

## 3. 理论依据：从人类机制到工程映射

把两份前置研究报告的结论逐条翻译成设计决策。凡是"人类有这个机制"而"工程上没有对应物"的，明确标为**不实现**——不假装。

### 3.1 记忆侧映射

| 人类机制（文献结论） | 工程对应物 | 实现位置 |
| :--- | :--- | :--- |
| 感觉记忆 0.25~1s / 2~4s，物理特征编码，极易消退 | **Sensory Ring**：环形缓冲，存原始 token 与哈希，TTL 2 轮，不落盘 | §8.1 |
| 短时记忆 5~20s，无复述即消退 | **Working Set**：当前 turn 的活跃 cell 引用，超时释放引用（不删数据） | §8.2 |
| 工作记忆容量 ≈ 4 组块（Cowan） | **4±1 槽位竞争工作空间**，硬上限 4，组块化 = 多 cell 打包进一槽 | §9.3 |
| 离散槽位 vs 共享资源之争 | 混合：槽位数固定，每槽精度随负载下降 | §9.3 |
| 海马负责**绑定**分散表征，不存细节 | **超图 Binder**：一 cell 绑定多模态槽位与跨 cell 关系，细节留残差 | §5.3 |
| 内嗅皮层是串行瓶颈 | **Encoder 单入口**：只有 `encode()` 能写晶格 | §7 |
| LTP 三特性：协同性、联合性、输入特异性 | **共激活强化**：同 turn 共现的 cell 间边权 +Δ；未共激活的边按比例衰减 | §10.2 |
| E-LTP 1~3h 不依赖蛋白合成 / L-LTP 依赖 | **热层（内存）/ 温层（SQLite）** 两级巩固，跨层迁移需重放 ≥2 次 | §10.2 |
| 睡眠 SO–SS–SPW-R 三重耦合驱动海马→皮层转移 | **NREM pass**：重放高频 cell，抽 schema，N 个情景 cell 合 1 个语义 cell | §10.3 |
| REM 期波峰回放稳定、波谷去强化 | **REM pass**：反事实重组生成联想边；情景 cell 情绪效价衰减 | §10.4 |
| 稳态突触下调、Homer1a 按比例降权 | **按比例降权**：所有边权乘 γ∈(0.9,0.99)，保留相对排序 | §10.5 |
| 艾宾浩斯曲线：负加速 | **幂律 R(t)=(1+F·t/S)^(−d)**；短时段的陡降由 TTL 承担，不进曲线 | §10.6 |
| 提取环境与编码环境一致时回忆更好 | **上下文线索键**：cell 携带编码时 topic/任务/情感指纹 | §9.2 |
| 启动效应（priming） | **1-hop 预热**：命中 cell 的直接邻居低权重进候选池 | §9.2 |
| 完全系列扫描（短时）/ 线索跳转（长时） | 槽内全扫，长时库索引跳转 | §9.4 |
| 记忆是建构性重构，重构发生在提取阶段 | **渲染即重构**：MRS 投影按当前目标重排字段 | §9.5 |
| 错误记忆：图式填空、事后信息效应、反复转述 | **矛盾检测 + 版本链**：不覆盖，建 `SUPERSEDES` 并保留双版本 | §7.6 |
| 主观确定性与客观准确性独立 | **双置信度**：`confidence` 与 `support` 分离，禁止相乘合并 | §5.4 |
| CREB 竞争决定哪些神经元进入 engram | **写入竞争**：相似度 > τ 时触发合并竞争，胜者得边权预算 | §7.5 |
| engram 在逆行性遗忘下仍保留 | **遗忘 = 降层 + 线索重建**，`include_archived` 可强制唤醒 | §10.6 |

### 3.2 情感侧映射

| 人类机制（文献结论） | 工程对应物 | 诚实度声明 |
| :--- | :--- | :--- |
| 内感受把"感知对象"与"感知主体"绑定，构成自我感基底 | **虚拟内稳态**：6 个真实可测的内部变量 | 这不是身体，是**运行时可观测量**。真实存在、会变坏、需调节，但不宣称有感受质 |
| 人为增加心率放大焦虑样反应；后脑岛是决定节点 | **变量→唤起的单调映射**，参数可标定、可消融 | 因果方向可测：拉高 `uncertainty`，观察澄清行为是否增加 |
| 同一躯体感受在不同情境被解读为恐惧或兴奋 | **评价先于标签**：PAD 由 6 维评价算出，情绪词只在渲染时生成 | 标签是投影，不是存储 |
| Barrett 四步：身体变化→感知→结合经验解释→情绪出现 | **四段管线**：interocept → core affect → appraisal×context → label | 第三步依赖用户 schema，这正是"越聊越准"的机制 |
| 情绪不是按钮式固定反应 | 同一输入在不同 mood/关系下产生不同 PAD 轨迹 | 可回放验证 |
| Damasio/LeDoux：情感处于意识核心 | 情感参与检索门控与策略选择，不是生成后的修饰层 | §11.6 策略表是硬约束 |
| 4E 具身性要求具身、嵌入、延展、生成 | 只满足"嵌入"与"延展"；**明确不满足具身** | 文档中不得声称具备具身性 |
| 现象意识不可由行为证据判定 | **不做任何现象意识声明**；`affect_report` 返回数值 | §19.2 |

### 3.3 明确不实现

写进 README 的 Known Limitations：

1. **不实现现象意识**，不模拟"内在体验"修辞。所有情感输出都是状态变量的投影。
2. **不实现神经发生**（对应"神经发生依赖性回路重排"）。用"高熵期随机剪枝"近似，效果不等价。
3. **不实现蛋白合成时间窗**。E-LTP/L-LTP 只借用为两级存储层。
4. **不实现跨模态感知**（v0.1/v0.2）。类型位预留，编码器未实现。
5. **不实现情绪传染式共情**。共情表现为关系模型更新，不是情绪同步。

## 5. 记忆表示：MemCell 七元组

### 5.1 定义

```
M = ⟨σ, E, G, Φ, A, R, τ⟩
```

| 符号 | 名称 | 类型 | 作用 | 为什么不是文字 |
| :--- | :--- | :--- | :--- | :--- |
| σ | Symbol Slot | 2048-bit SDR（k=8，密度 0.39%） | 离散身份、可哈希、可代数绑定 | 位运算，O(1) |
| E | Embedding | int8[256]（量化自 1024-d） | 连续相似度 | ANN 检索 |
| G | Graph | 有类型超边，边权 i8 | 关系、因果、时序、矛盾 | 图遍历 |
| Φ | Frame | 语义角色槽（8 类） | 结构化命题，可解绑查询 | 槽位填空，无句法分析 |
| A | Affect | 4×i16 + 6×i8 评价 | 情绪着色、检索门控 | 数值可加权 |
| R | Residual | zstd 字节 + sha256 + offset | **无损**回溯原文 | 唯一含文字处，默认不进上下文 |
| τ | Time | 4×i64 + 稳定性 S | 时序推理、遗忘 | 时间戳 |

### 5.2 为什么是这七个

每个字段对应一类必须被高效支持的运算，删任何一个就有一类查询退化：

- 删 σ → 无法精确符号匹配与矛盾检测。浮点对 `api_key` 和 `api-key` 的相似度是 0.93，判不出是否同一实体。
- 删 E → 无法召回"意思相近但用词完全不同"（"深色模式" vs "夜间主题"）。
- 删 G → 无法多跳（"上次那个 bug 是谁提的"→ 人 → 模块 → 模块的历史决策）。
- 删 Φ → 无法角色敏感推理（同一句话主客颠倒意思相反）。
- 删 A → 情感与记忆两条线断开。
- 删 R → 无损性丢失，只能摘要，无法回溯。
- 删 τ → 无法回答"什么时候"，无法遗忘，无法做时序矛盾检测。

### 5.3 超图而非普通图

记忆里大量关系是 n 元的：

> "上周三，张工在评审会上说 V2 的缓存方案要回滚。"

涉及 5 个实体。两两连边会爆炸成 10 条且丢失"同属一个事件"的整体性。超图用一条 n 元边表达，同时保留整体性。实现上退化为**星型结构**：一个 `event` 节点 + n 条 `ROLE_*` 边。代价是多一跳，收益是索引简单。

关系类型词表（u8，可扩展）：

| id | 关系 | 推理用途 |
| :--- | :--- | :--- |
| 0x01 | `IS_A` | 继承、传递闭包 |
| 0x02 | `PART_OF` | 聚合、部分匹配 |
| 0x03 | `CAUSES` | 因果链、反事实 |
| 0x04 | `BEFORE` | 传递闭包、时间线重建 |
| 0x05 | `SAME_AS` | 实体消解 |
| 0x06 | `CONTRADICTS` | 冲突检测 |
| 0x07 | `SUPERSEDES` | 版本链、时效判定 |
| 0x08 | `ABOUT` | 主题聚合 |
| 0x09 | `PREFERS` | 用户建模 |
| 0x0A–0x0C | `ROLE_AGENT/PATIENT/TIME` | 槽位回填 |
| 0x0D | `EVIDENCE` | 支撑度累计 |
| 0x0E | `ASSOC` | 发散游走 |
| 0x0F | `EVOKES` | 情感传播 |

### 5.4 双置信度

人类记忆最危险的特征是**主观确定性与客观准确性彼此独立**——内侧颞叶提供的"细节感"既能被真实痕迹激活，也能被建构过程激活。文本记忆库若只存一个 `confidence`，会把这个缺陷原样继承：模型越"自信"地误记，检索越优先返回它。

| 字段 | 含义 | 来源 | 更新 |
| :--- | :--- | :--- | :--- |
| `confidence` | 编码时自评 | 编码器 | 仅重新编码时更新 |
| `support` | 独立证据计数 | 每次出现同类断言 +1 | 单调递增，可被 `CONTRADICTS` 抵消 |

**禁止**相乘合并成单一分数。排序用 `rank = f(sim, support, confidence)`，`support` 权重更高——一条被 5 次独立确认的事实，即使单次编码置信度 0.6，也应排在单次高置信断言之前。

### 6.3 空间预算

一条 800 字的中文对话轮次，UTF-8 约 2.4 KB，token 约 800。编码后：

| 项 | 大小 | 说明 |
| :--- | ---: | :--- |
| 定长头 + SDR + emb + 槽位 + 边 | ≈ 812 B | 结构化基底 |
| 残差（zstd 压缩原文） | ≈ 1.0–1.2 KB | 中文 zstd 比约 0.42–0.50 |
| 合计 | ≈ 1.8–2.0 KB | **相对原文 0.75–0.85×** |

**所以存储层并不"压缩"。** 这点必须写在文档里，而不是用含糊话术糊过去。真实空间收益来自跨条目层面：

1. **残差共享**：同一段工具输出被多次引用时残差只存一份，多 cell 指向同一 offset（引用计数）。
2. **schema 抽象**：N 条同类情景 cell 巩固时合并为 1 条语义 cell，残差仍共享。
3. **冷层重编码**：冷层保留头 + SDR + 32 B PQ，emb 降到 32 B，残差外迁。

300 轮真实中文会话的**设计目标**是整体 0.45×–0.60×，由 §18 的 `storage_ratio` 验证。这是目标，不是既成事实。

### 6.4 "六易"如何被满足

| 要求 | 机制 | 复杂度 | 验证 |
| :--- | :--- | :--- | :--- |
| **易理解** | 定长头 + 固定槽位 + 自描述 schema；单条记录 812 B 内读完，无需 NLP | O(1) 字段访问 | 抽 100 条人工判读 |
| **易计算** | 全部算子为 popcount / 位置置换 / 点积 / 稀疏乘加；无字符串、无排序（kWTA 除外） | Jaccard 256 B = 3×32×u64 popcount | 微基准 < 80 ns |
| **易推理** | ① 槽位解绑回填 ② 关系代数（闭包/继承/矛盾） ③ 数值蕴含（时间区间、数量） | 单跳 O(deg)，k 跳闭包 O(V+E) | 合成推理集准确率 |
| **易发散** | 带温度图随机游走 + 情感偏置采样 + `ASSOC` 弱边 | O(k·d)，k≤4 | 联想多样性 |
| **易压缩** | 残差 zstd + 残差共享 + schema 抽象 + 冷层 PQ | — | `storage_ratio` |
| **易检索** | 四路索引：HNSW O(log n) / SDR 倒排 O(1)~O(n/64) / CSR O(deg) / B+tree | 见左 | p95 < 40 ms @ 100 万 cell |

### 6.5 SDR 代数（v0.2 修正版）

**算子定义**（稀疏集合语义，不是密集位向量语义）：

```
bind(f, role) = permute(f, Π_role)      // 角色置换，不是 XOR
unbind(x, role) = permuteInv(x, Π_role) // 逆置换，精确可逆
bundle(xs)    = ⋃ xs，若密度 > cap 则 kWTA 到 cap
jaccard(a, b)    = |a ∩ b| / |a ∪ b|    // 对称：cell ↔ cell（去重、合并）
containment(q, c) = |q ∩ c| / |q|       // 非对称：query → cell（检索）
```

`Π_role` 由 role 码的**全码哈希**经 Fisher-Yates 生成（必须哈希全部字，只哈希前两个字会让所有角色塌缩成同一张表，见 D-03c）。

**为什么这四条是对的**：

1. **精确可逆**：置换是双射，`unbind` 是逆置换，"给定命题问施事是谁"是 O(k) 而非 O(D)。
2. **密度精确保持**：8 位进、8 位出。对比 XOR 的对称差会翻倍到 16 位（D-03a）。
3. **角色正交**：不同 role 的置换表互不相关，因此叠加后的噪声是均匀散布的。
4. **噪声底极低**：两个无关单码的期望 Jaccard ≈ k/(2D−k) = 8/4088 ≈ **0.002**（实测 0.000）。对比 v0.1 的汉明相似度噪声底 0.96——差三个数量级，这才是检索能工作的前提。

**为什么必须有两个相似度，而不是一个**（这是 v0.1 之后的又一处校准错误，值得单独说）：

检索时两边的尺寸是**悬殊**的。query 是一个小 bundle（约 16 位），cell 是一个大 bundle（约 184 位）。此时 Jaccard 的上界是 `|q|/|c| ≈ 0.087`——**即使 query 的每一位都完全包含在 cell 里，Jaccard 也只有 0.087**，会被 `w_r·recency`（约 0.32）直接压死，完美的记忆匹配永远排不进槽位。

| 度量 | 完全命中 | 无关 | 动态范围 | 用途 |
| :--- | ---: | ---: | ---: | :--- |
| Jaccard(q,c)，尺寸悬殊 | 0.087 | 0.007 | 12× 但上界过低 | **不可用于检索** |
| Containment(q,c) | 1.000 | 0.090 | 11× 且上界正确 | **检索用这个** |
| Jaccard(c1,c2)，尺寸相当 | 0.9+ | 0.047 | 19× | 去重/合并用这个 |

所以：**对称比较（去重、合并、冗余惩罚）用 Jaccard；非对称检索（query → cell）用 containment。** 两者不可互换。

containment 的噪声底是 0.090（不是 0），因此进入打分前要做一次固定线性标定，保证跨轮可比：

```
sim_norm = clamp((containment − 0.09) / (1 − 0.09), 0, 1)
```

不要用"候选池内 min-max 归一化"——那会让同一 cell 在不同轮次的分数不可比，`ignition` 阈值就失去意义。

**容量**（数值全部来自 `mnemo-sdr-check.mjs` 实测）：

| 量 | 公式 | 实测 |
| :--- | :--- | :--- |
| 无关单码 Jaccard | k/(2D−k) | 0.000 |
| 无关 bundle(24) Jaccard | ≈ 2·(nk/D)/(1+nk/D) | 0.047 |
| bundle 密度（n=24） | nk/D | 9.13% |
| bundle 项数上限（密度 cap=12%） | cap·D/k | 30 |
| **工程建议上限** | rank-1 全对 | **24** |
| n=24 正确/错误成分区分度 | — | **2.7×** |
| n=30 区分度 | — | 1.6×（开始退化） |
| n=32 区分度 | — | 1.4×（不建议） |

**必须写明的三条约束**：

1. **解绑只能用 argmax，不能用绝对阈值。** n=24 时正确成分的 Jaccard 只有 0.043，错误成分 0.016——区分度 2.7×，靠的是排序而不是数值大小。任何"sim > 0.5 算命中"的写法在这个尺度下永不成立。
2. **bundle 之间的噪声底是 0.047，不是 0.002。** 两条无关记忆的 Jaccard 约 0.05，因此 §7.5 的去重阈值 0.85 有充足余量，但"相关"档的 0.45 必须高于这个底——留了 10 倍余量，安全。
3. **n>30 触发 WTA 后不可逆。** 被裁掉的位对应的成分无法解绑。这是**可测的退化**，不是 bug。§18.3 的消融专测这一项。

**为什么选 2048 而不是 1024**：D=1024、k=8 时噪声底 0.0039（尚可），但 bundle 可检索容量只有 ≈18，装不下一个含 6 个槽位 + 若干修饰的命题。2048 是"容量够用且每 cell 只多 128 字节"的折中点。

### 6.6 编码一个命题

以"用户上周说深色模式太刺眼"为例：

```
p = bundle(
      bind(SDR(用户),     Π_AGENT),
      bind(SDR(深色模式), Π_PATIENT),
      bind(SDR(刺眼),     Π_PRED),
      bind(SDR(上周),     Π_TIME),
      bind(SDR(否定),     Π_POLARITY)
    )
```

解绑查询"这个命题的受事是什么"：

```
q = unbind(p, Π_PATIENT)                 // 逆置换：把 PATIENT 的位放回原位
nearest = argmax_{x ∈ vocab} sim(q, SDR(x))   // 必须用 argmax，不是阈值
```

不需要句法树、依存分析、文字。注意 `bind` 的参数顺序是 **(填充值, 角色)**，v0.1 写反了——置换绑定不交换，顺序错了解出来是另一张表。

## 7. 写入路径：编码器

编码器是唯一能写晶格的入口（对应内嗅皮层的串行瓶颈）。接收 `session/event`，输出 0..N 个 MemCell。

### 7.1 五阶段

```
原始事件
  → ① 切分（proposition segmentation）
  → ② 槽位填充（frame filling）
  → ③ 表征生成（SDR + embedding）
  → ④ 情感评价（appraisal → PAD → importance）
  → ⑤ 冲突消解与落库（dedup / merge / supersede）
```

### 7.2 ① 切分：以命题为单位

一句话可能含 3 个可独立检索的事实；一段话也可能只有一个。切分目标是**原子断言**：单一主语 + 单一谓词 + 可判真假。

| 层级 | 方法 | 覆盖 | 成本 |
| :--- | :--- | :--- | :--- |
| L0 | 规则：句末标点 + 并列连词 + 转折词 | ~60% | 0 |
| L1 | 小模型单次调用（结构化输出） | +30% | ~200 in / 150 out |
| L2 | 延迟到巩固期批量处理（离线） | +10% | 离线 |

**关键约束**：L1 的输出不是自然语言，而是 JSON 数组的槽位填充结果。编码器从第一步起就不产生散文。

### 7.3 ② 槽位填充

固定 8 个槽位（与 FrameNet 核帧对齐后裁剪）：

| 槽位 | 语义 | 触发 |
| :--- | :--- | :--- |
| `AGENT` | 施事 | 谁做的 |
| `PATIENT` | 受事 | 对谁做的 |
| `PRED` | 谓词（归一化到词表 id） | 做了什么 |
| `TIME` | 时间（区间或点） | 何时 |
| `PLACE` | 位置/环境 | 何地 |
| `MANNER` | 方式 | 如何 |
| `GOAL` | 目的 | 为何 |
| `QTY` | 数量/程度 | 多少 |

槽位值三种编码：`REF`（指向实体 cell）、`LIT`（数值/枚举内联）、`UNK`（未填）。`UNK` 必须显式存——"未提及"与"填了空值"在推理时语义不同（前者不能做否定推理）。

### 7.4 ③ 表征生成

- **实体 SDR**：实体字符串 → 归一化（小写、去标点、同义词表）→ 稳定哈希 → 伪随机 k=8 稀疏码。同实体必得同码，跨进程稳定。**这不是语义哈希，只是稳定身份码**；语义相似性由 E 承担。这点必须写清，否则会被误认为"用哈希冒充语义"。
- **命题 SDR**：§6.6 的绑定-叠加。
- **Embedding**：优先用宿主已配置的 embedding 能力；否则本地 `bge-m3` 量化版。**不额外调用付费 API**，这是成本红线。

### 7.5 ⑤ 去重与合并竞争

按相似度分三档（阈值基于修正后的 Jaccard 尺度重新标定）：

| Jaccard | 动作 | 说明 |
| :--- | :--- | :--- |
| `> 0.85` 且槽位完全一致 | **合并**：`support++`、`stability × 1.3`、`t_access` 更新、残差共享 | 同一事实重复出现 |
| `0.45 < J ≤ 0.85` | **关联**：建 `SAME_AS` 或 `PART_OF`，不合并 | 相关但不同 |
| `≤ 0.45` | **新建** | 独立记忆 |

> **阈值为什么整体下移**：v0.1 的 0.95/0.80 是在"汉明相似度"尺度上拍的，而那个尺度的噪声底就有 0.96。Jaccard 尺度下，两条无关记忆的实测噪声底是 **0.047**（§6.5），同义改写大致落在 0.5–0.8，完全重复在 0.9 以上。
>
> **但这三个数是初始值，不是结论。** 必须由 §18.4 的去重集（2000 对人工标注）重新标定，标定前不要在文档里当成定论引用。当前的 0.45 相对噪声底留了约 10 倍余量，这是它可用的最低理由。

合并时执行**竞争**（对应 CREB 竞争性分配）：`support` 高者胜；平手 `importance` 高者胜；再平手 `t_ingest` 早者胜（先写先得，避免顺序依赖导致不可复现）。

### 7.6 矛盾：不覆盖，建版本链

检测到同 `(AGENT, PRED)` 但 `PATIENT`/`POLARITY` 冲突时：

```
旧: (用户, PREFERS, 深色模式, 否定, t=0910)
新: (用户, PREFERS, 深色模式, 肯定, t=0914)
```

1. 新 cell 建 `CONTRADICTS` 边指向旧 cell；
2. 若时间上后者覆盖前者，再建 `SUPERSEDES`；
3. 旧 cell `flags.bit2 = 1`，`importance × 0.6`；
4. 写 `memory/conflict` 事件。

检索默认返回**最新且 support 最高**的版本，渲染时附 `↑` 标记。这对应人类记忆的"事后信息效应"——差异本身有价值，不该被静默抹平。

> 有意偏离数据库的 UPDATE 语义。理由：记忆的时间演化是语义的一部分。用户改主意这件事，比用户当前偏好什么，往往更有信息量。

### 7.7 脱敏与密钥占位符（V-06）

0.2.1 起 DSH 会把消息中的密钥/令牌默认打码。编码器必须处理两种来源：

| 情况 | 处置 |
| :--- | :--- |
| 原文含疑似密钥（正则命中） | 残差中替换为 `«SECRET:n»`，`flags.bit4=1`，原文不入库 |
| 消息中已是 DSH 脱敏占位符（`***` 等） | **禁止**把占位符当真实值编码；该槽位降为 `UNK` 并记 `redacted` |

第二条是 v0.1 没有的坑：如果不判断，模型会记下"用户的 API key 是 `***`"，然后在后续对话里自信地复述这个假事实。

## 8. 存储引擎与索引

### 8.1 Sensory Ring（感觉记忆）

- 固定 2 轮容量的环形缓冲，存原始 `ContentBlock` + 内容哈希。
- TTL 2 轮后失效，**不落盘**。
- 用途：① 检测"用户重复粘贴同一段内容"（哈希命中 → 不重复编码）；② 为残差提供去重键。
- 容量默认 64 KB，超出覆盖最旧。

### 8.2 Working Set（工作记忆）

- `Map<cell_id, activation: f32>`。
- 生命周期单 turn。turn 结束不删数据，只释放引用。
- 硬上限 16 个 cell（按 activation 截断）。这是**引用集**，与 4±1 槽位是两层概念：Working Set 是"这轮摸过的所有东西"，槽位是"这轮真正摆到模型眼前的四件事"。

### 8.3 Long-Term Lattice

```sql
CREATE TABLE cells (
  cell_id     INTEGER PRIMARY KEY,
  kind        INTEGER NOT NULL,
  tier        INTEGER NOT NULL,
  flags       INTEGER NOT NULL,
  t_from      INTEGER NOT NULL, t_to INTEGER NOT NULL,
  t_ingest    INTEGER NOT NULL, t_access INTEGER NOT NULL,
  access_cnt  INTEGER NOT NULL DEFAULT 0,
  stability   REAL    NOT NULL DEFAULT 7.0,
  importance  REAL    NOT NULL DEFAULT 0.5,
  valence     INTEGER NOT NULL DEFAULT 0,
  arousal     INTEGER NOT NULL DEFAULT 0,
  dominance   INTEGER NOT NULL DEFAULT 0,
  salience    INTEGER NOT NULL DEFAULT 0,
  provenance  INTEGER NOT NULL, trust INTEGER NOT NULL,
  sdr         BLOB    NOT NULL,   -- 256 B
  emb         BLOB,               -- 256 B int8 / 32 B PQ
  slots       BLOB    NOT NULL,
  residual_sha BLOB, residual_off INTEGER, residual_len INTEGER
);

CREATE TABLE edges (
  src INTEGER NOT NULL, dst INTEGER NOT NULL,
  rel INTEGER NOT NULL, weight INTEGER NOT NULL,
  PRIMARY KEY (src, dst, rel)
);

CREATE TABLE residuals (
  sha BLOB PRIMARY KEY, offset INTEGER NOT NULL,
  raw_len INTEGER NOT NULL, comp_len INTEGER NOT NULL,
  ref_cnt INTEGER NOT NULL DEFAULT 0, codec TEXT NOT NULL DEFAULT 'zstd-19'
);

CREATE TABLE cell_sources (
  cell_id INTEGER NOT NULL, session TEXT NOT NULL, seq INTEGER NOT NULL,
  PRIMARY KEY (cell_id, session, seq)
);

-- v0.2 新增：渲染快照（解决 D-05）
CREATE TABLE recall_snapshots (
  snap_id   BLOB PRIMARY KEY,     -- blake3(rendered)
  rendered  TEXT NOT NULL,
  tokens    INTEGER NOT NULL,
  created   INTEGER NOT NULL
);
```

四个索引：

| 索引 | 结构 | 服务查询 |
| :--- | :--- | :--- |
| `idx_ann` | HNSW（M=16, ef=64）on `emb` | 语义近邻 |
| `idx_sdr` | 位图倒排：bit → cell_id 列表（64-bit 分桶） | 符号精确/近精确 |
| `idx_edges` | CSR 邻接（出边有序） | 图游走 |
| `idx_time` | `(t_from, t_to)` B+tree | 时间范围、时序推理 |

### 8.4 分层与迁移

| 层 | 介质 | 内容 | 迁移条件 |
| :--- | :--- | :--- | :--- |
| 热 | 内存 | 最近 2000 cell 全量 | 30 分钟未访问 → 温 |
| 温 | SQLite | 全量（emb 256 B） | `R(t) < 0.35` 或 30 天未访问 → 冷 |
| 冷 | SQLite + 对象存储 | 头 + SDR + **32 B PQ**，残差外迁 | 手动归档 |
| 归档 | 头 + 残差指针 | 仅 `include_archived` 可达 | 不自动删除 |

**冷层保留 PQ 码**（32 B，8 段 × 4 bit）而不是直接丢 emb——这是 D-07 的修复。丢掉 emb 后语义召回就没了，而 SDR 是身份码，恢复不出语义。32 B 的 PQ 码足够做粗排（recall@64 约 0.85），精排时再 rehydrate（重算 embedding，代价可控）。

**任何层都不自动物理删除。** 删除只能由用户显式发起（`memory_forget`），且必须写 `memory/evict`。遗忘应该是"取不到"，不是"不存在"——对应 engram 在逆行性遗忘下仍保留的发现。

### 8.5 并发模型（D-08）

| 角色 | 事务 | 说明 |
| :--- | :--- | :--- |
| recall（读） | 只读，WAL 快照 | 不阻塞写，永远读已提交 |
| encode（写） | `BEGIN IMMEDIATE`，单事务写 cell+edges+source | 短事务，毫秒级 |
| consolidate（写） | `BEGIN IMMEDIATE`，整个 pass 一个事务 | 长事务；与 encode 串行 |
| reindex（维护） | 独立连接 + 影子表，完成后原子切换 | 不阻塞读 |

巩固期间 recall 读到的是 pass 开始前的快照——这保证召回不会返回"指向已合并消失 cell 的边"。代价是 pass 期间召回可能稍旧，可接受（巩固是秒级）。

## 9. 检索路径与 Token 经济学

### 9.1 四路并行召回

```
Query
 ├─ Q1 语义路：emb → HNSW → top 64
 ├─ Q2 符号路：query 中实体 → SDR → 倒排 → top 64（精确）
 ├─ Q3 图路：Q1/Q2 的 top 8 作种子 → 2 跳加权扩散 → top 64
 └─ Q4 时间路：query 含时间表达式 → 时间轴范围 → top 64
        ↓
     合并去重（cell_id）→ 候选池 ≤ 200
        ↓
     归一化打分 → 4±1 槽位竞争 → 渲染
```

四路并行不是"多召回总没坏处"，而是针对四类不同查询：

| 查询类型 | 例 | 主通道 | 其他通道贡献 |
| :--- | :--- | :--- | :--- |
| 语义近似 | "我之前说过的那个界面问题" | Q1 | Q3 补多跳 |
| 精确事实 | "API key 在哪个文件" | Q2 | Q1 几乎无用 |
| 多跳推理 | "上次那个 bug 是谁提的" | Q3 | Q2 定锚点 |
| 时间定位 | "三周前我们定了什么" | Q4 | Q1 定主题 |

**Q1 单独使用时对标识符类查询几乎无效**，这是向量检索的已知弱点，也是必须保留 Q2 的原因。

### 9.2 打分函数（归一化版，修 D-04）

v0.1 的分数是 7 项加权和，最大约 2.5，却用 0.45 做阈值——阈值形同虚设。修正为**按激活权重归一化**：

```
raw(c) = w_s·sim + w_r·recency + w_f·log1p(cnt)/log1p(100)
       + w_a·congruence + w_g·goalRel + w_c·cueMatch − w_i·interference

score(c) = raw(c) / Σ_active_weights        // ∈ [0,1]，可比较
```

`Σ_active_weights` 只累加**当前可用**的项（例如无 goal 时不计 `w_g`），因此不同上下文下的分数仍可比。各分量本身归一化到 [0,1]：

| 分量 | 定义 | 说明 |
| :--- | :--- | :--- |
| `sim` | 四路各自归一化后取 max | SDR 路用 `containment` 并做 §6.5 的固定标定；语义路用 cosine；图路用 `1/(1+hop)`；时间路用区间重叠率 |
| `recency` | `R(t)`，即遗忘曲线当前值 | 复用 §10.6，不另造公式 |
| `freq` | `log1p(access_cnt)/log1p(100)`，封顶 1 | 复述强化 |
| `congruence` | `1 − |v_c − v_mood|/2`，再乘平滑权重 | 见下 |
| `goalRel` | 与当前 goal 的 SDR 重叠 + 实体交集 | 无 goal 时为 0 且不计权重 |
| `cueMatch` | 编码时 topic/任务指纹与当前的一致度 | 情境依赖效应 |
| `interference` | 与已入选槽位的最大 Jaccard | 冗余惩罚 |

**心境一致性的权重是平滑的**（修 v0.1 的硬跳变）：

```
w_a_eff = w_a · clamp((mood.valence + 0.5) / 0.5, 0, 1)
```

`mood.valence ≥ 0` 时满权重 0.25；降到 −0.5 时线性归零。v0.1 用的是 `if (mood.v < -0.5) 禁用`，会在 −0.49 与 −0.51 之间突变，导致检索行为不连续。

**默认权重**：

| 权重 | 默认 | 依据 |
| :--- | ---: | :--- |
| `w_s` | 1.00 | 主信号 |
| `w_r` | 0.35 | 近期优先 |
| `w_f` | 0.20 | 复述强化 |
| `w_a` | 0.25 | 心境一致性（上限，防负向自强化） |
| `w_g` | 0.40 | 任务相关优先 |
| `w_c` | 0.30 | 情境依赖 |
| `w_i` | 0.50 | 冗余惩罚 |

### 9.3 4±1 槽位竞争

这是本方案在架构层面最实质的一件事：**给 LLM 装一个真正的容量瓶颈**。

前置研究指出，标准 Transformer 缺乏真正的瓶颈竞争——上下文窗口更像一个容量很大的记事本，而不是必须竞争才能进入的稀缺通道（GWT-2 缺失）。MnemoVault 在**上下文入口处**人为制造这个瓶颈：

```
候选池 200 → 归一化打分 → 排序
  ↓
取前 N_slot（默认 4，可调 3~5）
  ↓
每槽精度预算：slot_capacity ∈ [1,3]，由 slot 内最高分决定
  ↓
总条目 = min(maxEntriesPerTurn, Σ slot_capacity)
  ↓
若 score < ignition(0.42) → 该槽留空，不注入
```

三个设计点：

1. **默认 4，上限 5**。对应 Cowan 的"神奇数字 4"（控制复述与组块后的中央注意纯容量），而非 Miller 的 7±2。配置允许 3~5 是为了适配不同模型，但**不建议超过 5**——超过就不再是瓶颈，退化为 top-k。
2. **组块化**。一槽可打包多个高度相关的 cell，复刻"不扩槽位数、只扩单槽内容"的机制。
3. **空槽合法**。宁可只给 2 条也不凑满。直接省 token，也避免无关记忆污染上下文。

**槽内全扫，槽间跳转**：4 个槽位全部参与排序（成本可忽略），长时库用索引跳转。对应短时记忆的穷举扫描与长时记忆的线索跳转。

### 9.4 渲染：MRS

渲染是**唯一花 token 的环节**，因此是整个设计的经济核心。

**五条原则**：

1. **图例一次，正文极简**：首轮注入图例（约 140 token，可被 prefix cache 命中），此后每条 15–25 token。
2. **列式优于行式**：批量记忆共享字段只写一次。
3. **数值优于自然语言**：`V:+0.6` 优于"用户比较喜欢"。
4. **字节稳定**：同 cell 同 query 必须逐字节一致，否则 prefix cache 失效。
5. **可逆指针**：每行带 `cell_id` 前缀，模型可调 `memory_expand` 展开。

#### 图例

```
[MEM v2] 每行一条记忆，字段以 | 分隔。
M=id前缀 T=时间(MMDD) P=来源(u用户/a助手/t工具/w网络/i推断)
F=帧类型 K=键值 V=效价[-1,1] S=显著度 C=置信度 ↑=有过变更
```

#### 行式（默认）

```
M:7f3a|T:0914|P:u|F:pref|K:ui.theme=dark|V:+0.6|S:0.7|C:0.95
M:2c19|T:0902|P:u|F:pref|K:ui.font=mono|V:+0.4|S:0.5|C:0.90|↑
M:b104|T:0821|P:a|F:fact|K:repo.lang=ts|V:0|S:0.6|C:0.99
```

三条 ≈ **68 token**；等价自然语言约 150 token。

#### 列式（高密度）

```
M[7f3a,2c19,b104]|T[0914,0902,0821]|P[u,u,a]
F[pref,pref,fact]|K[ui.theme=dark,ui.font=mono,repo.lang=ts]
V[.6,.4,0]|S[.7,.5,.6]|C[.95,.90,.99]
```

同三条 ≈ **42 token**。只在 `surfaceMode: "compact"` 时用。

#### 情感状态行

```
A|mood:+0.20/0.45/0.10|rel:trust.72,fam.55|pol:verb-1,temp-0.05,clar+1
```

约 **28 token**。让模型知道"该用什么语气、多谨慎、要不要多问一句"，而不需要在 system prompt 写大段人设。

#### id 前缀的稳定性（修 v0.1 的隐患）

v0.1 说"冲突时自动加长到 6 位"，这会让同一 cell 在不同轮渲染不同，破坏字节稳定性。修正为：**id 长度在会话首轮确定并写入图例**（`M=id前缀4位`），整会话固定；若某批内出现碰撞，改为在该批内追加序号（`7f3a#2`），**不改长度**。

### 9.5 Token 总账（修 D-08 的遗漏）

v0.1 只算了 surface，没算编码成本。真实成本必须把三条路径分开：

| 路径 | 每轮用量 | 模型 | 相对价格 | 折合主模型 token |
| :--- | :--- | :--- | :--- | ---: |
| 编码（L1 切分+槽位） | 200 in + 150 out | 小模型 | 0.1× | ≈ 35 |
| 向量化 | 1 次，≤1000 字 | embedding | 0.02× | ≈ 2 |
| 召回 | 0（纯数值） | — | — | 0 |
| **Surface 注入** | **184** | **主模型** | **1.0×** | **184** |
| **合计** | — | — | — | **≈ 221** |

对照：

| 方案 | 折合主模型 token/轮 | 说明 |
| :--- | ---: | :--- |
| 无记忆 | 0 | 跨会话能力为零 |
| 文本 RAG（top-6） | 1,800–2,600 | 每块 260–380 + 指令 120 |
| DSH compaction 摘要 | ~500（一次性） | 压对话不压知识 |
| **MnemoVault 行式** | **≈ 221** | 对 RAG 省 **≈ 90%** |
| **MnemoVault 列式** | **≈ 169** | 对 RAG 省 **≈ 93%** |

> 编码成本是 v0.1 漏掉的 35 token。加上之后结论不变（省 90% → 省 90%），但**账必须算全**，否则一上量就会被成本对账打脸。

**省 token 的四个来源**（按贡献排序）：

1. **结构化取代散文**（~55%）：同信息字段化后 token 降为 1/6~1/8。
2. **摘要 + 按需展开**（~25%）：`memory_expand` 只在真要原文时付费。复刻人类"先回忆大意、需要时再重构细节"。
3. **不注入无关记忆**（~15%）：空槽合法 + 显著度阈值。
4. **前缀缓存友好**（~5%，乘法效应）：字节稳定让 prefix cache 命中率达 90%+。

**必须写明的代价**：结构化渲染要求模型学会读 MRS。弱模型可能解析失败、退化为忽略记忆。因此提供 `surfaceMode: "prose"` 降级（展开成短句，token 约 2.5×，仍优于 RAG）。这条降级路径不是可选项——任何"必须让模型适应我的格式"的设计，换模型就会崩。

## 10. 巩固、遗忘与睡眠双相

### 10.1 为什么离线巩固

在线编码只能做局部决策（这条记不记、记成什么形状）。全局决策——哪些该抽象成规律、哪些该降权、哪些被取代——需要看整体分布，必须离线。

| 相位 | 人类功能 | 工程对应 |
| :--- | :--- | :--- |
| NREM | 海马→皮层转移 | 重放高频 cell，抽 schema，合并同类 |
| REM | 整合、创造性连接、情绪效价降低 | 反事实重组生成联想边，情景记忆情绪衰减 |
| 主动遗忘 | 稳态下调、按比例降权 | 全边权乘 γ，弱边剪除，热层清空 |

### 10.2 触发与锁

```ts
passDue = (turnsSinceLastPass >= 20)
       || (cellsSinceLastPass >= 200)
       || (idleMs >= 90_000 && dirty)

memory/consolidate/start  →  ...  →  memory/consolidate/end
// 未匹配的 start 会阻塞后续 pass（可检测的遗留锁）
```

锁必须写在 Session Log 而不是内存里，否则崩溃后无法判断上次 pass 是否完成。这与 DSH compaction 的 `compaction/start` / `compaction/end` 同构，有意对齐。

幂等性：`passId = blake3(sessionId‖startSeq)`，重复执行同一 passId 不产生新边（写前查重）。

### 10.3 NREM pass：抽象与合并

```
1. 取本窗内 access_count ≥ 2 的 cell
2. 按 (kind, 主实体, PRED) 分组
3. 组内 ≥ 3 条且槽位高度重合 → 生成 1 条 kind=semantic 新 cell
   · 槽位取众数，冲突槽降为 UNK 并记 disputed
   · support = Σ 子项 support
   · 子项全部建 PART_OF 指向新 cell
   · 新 cell 残差 = 最短子项残差（共享，不复制）
4. 重算边权：共激活过的边 × (1 + 0.15·log(1+coact))
5. 写 memory/consolidate
```

对应系统巩固：情景记忆（依赖海马索引）逐渐转移为语义记忆（不依赖具体时空）。判据很朴素——**同一规律被三次以上独立观察到，就抽出来单独存**。

### 10.4 REM pass：发散与情绪衰减

**发散**：

```
for each seed in 高频 cell:
  for hop in 1..3:
    候选 = 按边权 × exp(-hop/τ) 采样，温度 T_div
    若候选对从未共现 → 建 ASSOC，weight=0.3
    若语义相似但情感效价相反 → 建 CONTRADICTS，weight=0.5
```

"语义相似但情感相反"的配对最有价值——它往往对应"用户前后矛盾"或"被忽略的替代方案"。纯向量检索永远发现不了。

**情绪衰减**：

```
for c in episodic_cells:
  c.valence  *= 0.92
  c.arousal  *= 0.94
  c.salience *= 0.96
  if |c.valence| < 0.05: c.valence = 0
  // slots / sdr / 残差 全部不动
```

关键：**只动情感维度，不动内容维度**。对应 REM 睡眠的天然情绪调节，也对应 PTSD 再巩固干预的目标（不抹除记忆，只削弱情绪负载）。人格锚 cell（`flags.bit1`）不参与。

### 10.5 遗忘：三条通路

| 通路 | 机制 | 人类对应 |
| :--- | :--- | :--- |
| **按比例降权** | 所有边权 × γ，γ∈[0.90,0.99]，默认 0.95 | Homer1a 介导的按比例下调：保留相对排序，只压刻度 |
| **弱边剪除** | weight < 8（i8 尺度）且 90 天未共激活 → 删边（不删 cell） | 稳态突触下调，提高信噪比 |
| **降层** | `R(t) < 0.35` → 温降冷，emb 转 PQ | SPW-R 介导的海马清除（腾空而非销毁） |

按比例而非按绝对值降权是最重要的一条：保证**记忆之间的相对强弱结构不变**，只让整体刻度下降。既释放资源，又不会打乱"哪些更重要"的排序。

### 10.6 遗忘曲线（v0.2 重写，修 D-06）

v0.1 用 `R(t)=exp(−t/S)` 配 `S₀=1.0` 天，导致 1.05 天就降层，与"语义记忆衰减慢"矛盾；而且单指数根本拟合不出艾宾浩斯的形状（20 分钟丢 42%，24 小时丢 66%，之后极长尾）。

v0.2 改**幂律**（FSRS 形式）：

```
R(t) = (1 + F·t/S)^(−d),   F = 19/81 ≈ 0.2345,  d = 0.5
```

构造性质：`t = S` 时 `R = 0.9`。所以 **S 的语义是"可提取性降到 0.9 所需的天数"**，比"稳定性"这个抽象词好用得多。

三档 profile 只改 S，不改形状：

| profile | S₀ | R(1d) | R(7d) | R(30d) | R(90d) | 用途 |
| :--- | ---: | ---: | ---: | ---: | ---: | :--- |
| `procedure` | 30 d | 0.996 | 0.974 | 0.900 | 0.766 | 技能、约定 |
| `semantic` | 7 d | 0.984 | 0.900 | 0.706 | 0.499 | 事实、偏好（默认） |
| `episodic` | 2 d | 0.946 | 0.741 | 0.470 | 0.294 | 具体事件 |

`demoteAt = 0.35` 对应 `t/S ≈ 30.5`（解 `(1+0.2345x)^-0.5 = 0.35` 得 `x ≈ 30.54`）：semantic 约 214 天、episodic 约 61 天才会因可提取性降层。单看这个数会显得"太慢"，但 §8.4 的降层条件是 **`R<0.35` 或 `30 天未访问`**，后者通常先生效——曲线管"想不想得起来"，访问间隔管"还用不用得上"，两个维度不该混成一个阈值。

**艾宾浩斯的 20 分钟数据点不进这条曲线。** 那个量级属于感觉/短时记忆，由 §8.1 的 TTL（2 轮）与 §8.2 的 Working Set 承担。v0.1 试图用一条曲线同时拟合 20 分钟与 30 天，是方法论错误。

**复述增益**：

```
S' = S · (1 + 0.6·(1 − R)) · spacing_bonus
spacing_bonus = min(2.0, 1 + 0.3·log1p(Δt_prev / S))
```

对应过度学习与间隔效应，且都有上限，防止 S 无限膨胀。

## 11. 情感系统

### 11.1 核心立场：给 AI 一个"由运行状态构成的身体"

前置研究结论很硬：如果情感的本质是身体内感受信号的预测性解释，那么没有身体、没有内稳态需求、没有生理反馈回路的纯文本系统，从根本上缺乏产生真正情感的基质。这个判断不接受辩驳。

但它留下一个工程缝隙：**"身体"不必须是碳基的，只需要是一组"会变坏、需要维持、可观测"的内部变量。**

| 变量 | 符号 | 取值范围 | 为什么会变坏 | 可观测证据 |
| :--- | :--- | :--- | :--- | :--- |
| 任务负荷 | `load` | [0,1] | 并行子任务多、上下文长 | 活跃 job 数、上下文 token 占比 |
| 不确定性 | `uncert` | [0,1] | 检索命中率低、工具连续失败 | recall 分数分布熵、工具错误率 |
| 冲突度 | `conflict` | [0,1] | 记忆互相矛盾、指令冲突 | `CONTRADICTS` 边密度 |
| 关系张力 | `strain` | [0,1] | 用户否定、纠正、重复追问 | 负向评价累积、重复提问率 |
| 目标进度 | `progress` | [0,1] | 计划滞后、阻塞 | `goal/change` 的 phase 与 round |
| 预算余量 | `budget` | [0,1] | token/时间/调用次数消耗 | TokenLedger、计时器 |

这六个量不是修辞，是**运行时真实可测的状态**。它们会变坏，变坏会影响表现（负荷高→更易出错），因此系统"需要维持"它们——这是 Seth 内稳态版本要求的那件事的最小可行实现。

**必须同时声明的边界**：这满足"有需要维持的内部状态"，**不满足**"有主观体验"。前者是可测的功能属性，后者不可由行为证据判定。文档、代码注释、对外表述三处都必须守住这条线。

### 11.2 四段管线

```
① 内感受  interocept()  →  i ∈ R⁶
② 评价    appraise(msg, i, ctx) →  a ∈ R⁶  (goal_rel, goal_con, agency, certainty, novelty, norm)
③ 核心情感 coreAffect(a, i) →  PAD + salience
④ 标签    label(PAD, context) →  仅在渲染时生成，不入库
```

对应 Barrett 四步：身体变化 → 感知 → 结合经验解释 → 情绪出现。第三步由 §11.5 的用户 schema 提供，这正是"越聊越准"的落点。

### 11.3 从评价到 PAD

```ts
const V = Math.tanh(1.2*a.goalRel*a.goalCon + 0.4*a.novelty*a.goalCon + 0.3*a.norm);
const A = Math.tanh(0.8*a.novelty + 0.6*Math.abs(a.goalCon)*a.goalRel + 0.5*i.load);
const D = Math.tanh(0.7*a.agency + 0.3*a.certainty - 0.2*i.uncert);
const S = Math.tanh(0.9*a.goalRel + 0.7*Math.abs(a.goalCon) + 0.4*a.novelty);
```

设计要点：

- `tanh` 保证有界且两端饱和——情绪不会无限放大。
- `arousal` 显式依赖 `load`：负荷高时同样评价产生更高唤起。对应"人为增加心率放大焦虑样反应"的因果方向。
- `dominance` 依赖 `uncert`（负向）：不确定性降低掌控感。
- 所有系数可配置、可消融，是一个**可标定的参数化模型**，不是拍脑袋。

### 11.4 心境与情绪

| 层 | 时间常数 | 更新 | 作用 |
| :--- | :--- | :--- | :--- |
| 情绪 | τ ≈ 1 turn | 直接由 PAD 得到 | 影响本轮渲染与策略 |
| 心境 | τ ≈ 20 turns | `m ← m + (e − m)/τ` | 影响检索门控与整体语气 |

两层的存在解释了人类的基本现象：单次事件让人"生气"，但一整天"心情"不会翻转。工程上这层是**稳定性来源**——没有 mood 积分，情感就是逐轮跳变的噪声，persona 会碎。

### 11.5 关系模型：越聊越准的机制

每个用户一份 `RelationalModel`（`kind=5` 的 cell，独立于情景记忆）：

| 字段 | 范围 | 更新规则 | 语义 |
| :--- | :--- | :--- | :--- |
| `trust` | [−1,1] | `t ← clamp(t + η·(kept − 3·broken))`，η=0.02 | 承诺兑现 vs 违背，违背权重 3× |
| `familiarity` | [0,1) | `1 − exp(−n_turns/40)` | 交互量，单调 |
| `attunement` | [0,1] | 见下 | 风格匹配度 |
| `boundaries` | set | 用户说"不要…"时写入，永不自动移除 | 硬约束，优先级最高 |
| `repairDebt` | [0,∞) | 每次误解 +1，成功修复 −1 | 未修复的裂痕 |

**`attunement` 的事件来源（修 D-12）**。v0.1 假设有 `affirmed`/`corrected` 事件，但没说谁产生。v0.2 用三条启发式，各自带置信度，低置信不更新：

| 信号 | 判定规则 | 置信度 | 效果 |
| :--- | :--- | :--- | :--- |
| 明确肯定 | 用户消息含"对/就是这样/没错/很好"，且下一轮未纠正 | 0.9 | `+0.03` |
| 明确纠正 | 用户消息含"不对/我说的是/不是这个意思"或重复同一请求 | 0.85 | `−0.05` |
| 隐式接受 | 用户直接推进到下一话题，无异议 | 0.4 | `+0.01` |

单次更新量小（0.01–0.05）且需要累积，避免一句话把关系状态打翻。

三条关键设计：

1. **不对称更新**：负面权重是正面的 3 倍。符合人类关系的不对称性（信任建立慢、崩塌快），也是安全设计——让系统更保守。
2. **boundaries 只增不减**：用户划的边界不能被"后来聊得好"自动撤销，只能由用户显式解除。这是隐私与尊重问题，不是模型问题。
3. **attunement 驱动 persona 微调**：高 → 更简洁少解释；低 → 更多澄清与铺垫。让"越聊越合拍"变成可测量、可回放的参数变化，而不是玄学。

### 11.6 情感 → 行为：策略表（硬约束）

情感若不影响行为，就只是装饰。以下映射**强制**，且可回归测试：

| 状态条件 | 行为改变 | 幅度 |
| :--- | :--- | :--- |
| `uncert > 0.7` | 澄清倾向 +2；先问再做 | 每轮最多 1 个澄清问题 |
| `load > 0.8` | 输出精简 −1 档；主动拆分任务 | 目标句数 ×0.7 |
| `strain > 0.5` | 语气降温；增加确认句；降低玩笑 | 情感词密度 ×0.5 |
| `conflict > 0.6` | 显式列出矛盾并要求裁决 | 必须引用两条冲突记忆 id |
| `progress < 0.3` 且轮次 > 8 | 主动重述目标并提议收窄范围 | 每 4 轮最多 1 次 |
| `trust < 0.25` | 高风险工具调用转 `ask` | 由 `tools/pre-execute` 执行 |
| `mood.valence < 0` | 心境一致检索权重线性下降 | 见 §9.2 |
| `budget < 0.2` | 停止发散游走；`surfaceMode` 切列式 | 省 token |

> `trust` 的阈值从 v0.1 的 `< 0` 改为 `< 0.25`（修 D-11）。原条件对新用户永不成立——新用户 trust 从 0 开始，永远不会被要求确认，这与"陌生人应更谨慎"的直觉正好相反。

### 11.7 三个演化环路

"情感随对话不断完善"必须落到三个具体环路，否则是空话：

| 环路 | 周期 | 输入 | 输出 | 持久化 |
| :--- | :--- | :--- | :--- | :--- |
| **快环** | 每轮 | 本轮消息 + intero | 本轮 PAD + 策略 | `affect/appraisal` |
| **慢环** | 每会话 | 本会话 PAD 序列 | mood 更新、关系模型更新、persona 微调 | `affect/state` |
| **离线环** | 每 N 会话 | 跨会话 cell 分布 | 用户 schema（"这个人是什么样"）、情感再标定 | `kind=3` schema cell |

离线环是"完善"的关键：把 50 次交互里散落的情感反应，抽象成一条关于这个人的 schema——"他在被追问细节时容易烦躁，但在被肯定方向后配合度很高"。这条 schema 反过来成为下次评价的先验，于是第一次交互就能猜得比较准。这是人类"熟悉一个人"的机制，也是本系统唯一真正的"学习"。

### 11.8 人格漂移的边界（修 D-13）

情感演化最大的工程风险是 **persona 崩塌**：无限漂移会让助手在 100 轮后变成另一个人。

三道约束：

1. **锚定**：`persona_0` 存为不可衰减的 `kind=4` cell（`flags.bit1=1`）。
2. **有界漂移**（仅超界时钳制）：
   ```ts
   const d = sub(persona, persona0);
   const n = norm(d);
   persona = n > EPS ? add(persona0, scale(d, EPS / n)) : persona;
   ```
   v0.1 写的是 `persona0 + EPS·d/‖d‖`，在 `‖d‖ < EPS` 时会把偏移**放大**到 EPS——一个小扰动被凭空放大。修正为"只在超界时收缩"。
3. **可回滚**：persona 版本链存 `SUPERSEDES`，`/mnemo persona rollback <rev>` 可回滚。

## 12. UI 与可操作性

v0.1 完全没写这一块——一个参数有 40 项、行为依赖六个隐变量的系统，如果没有可操作界面，等于不可用。这一章定义三件事：**在哪里调、调什么、调完怎么知道有没有用**。

### 12.1 三个入口，一条原则

| 入口 | 位置 | 解决什么 | 频次 |
| :--- | :--- | :--- | :--- |
| **设置面板** | Settings → MnemoVault（schema 驱动表单） | 调参数、换预设档 | 低频、深思 |
| **侧栏面板** | 右侧栏「更多」→ 记忆（0.2.1-rc.3 起该入口常驻） | 看记忆、改记忆、删记忆 | 中频、日常 |
| **命令** | 输入框 `/mnemo …` | 快捷动作、诊断 | 高频、即时 |

一条原则：**任何参数都必须能在三秒内找到，并且改完立刻能看出影响。**

这条原则的直接推论是：设置面板里每个参数旁边必须显示**当前实际值 + 影响预估**（token / 召回率 / 延迟），而不是一个孤零零的滑块。

### 12.2 设置面板：schema 驱动

DSH 的插件配置由 `Config`（schemastery）声明，设置面板据此生成表单。因此**不要手写 UI 表单**，把 `Config` 写清楚就够了——这是"可操作性"的最低成本实现，也是唯一不会随 DSH 升级而失效的实现。

```ts
export const Config: z<Config> = z.object({
  preset: z.union([
    z.const('lean'), z.const('balanced'), z.const('fidelity'), z.const('custom'),
  ]).default('balanced').description('预设档；选 custom 才启用下方细项'),

  maxSlots: z.number().min(3).max(5).default(4)
    .description('竞争槽位数。越大越全但越贵：+1 槽约 +45 token/轮'),

  surfaceMode: z.union([
    z.const('rows'), z.const('compact'), z.const('prose'),
  ]).default('rows').description('渲染格式。compact 省 25% token，prose 兼容弱模型'),

  forgettingProfile: z.union([
    z.const('procedure'), z.const('semantic'), z.const('episodic'),
  ]).default('semantic').description('遗忘速度档位，只改 S₀ 不改曲线形状'),

  affectEnabled: z.boolean().default(true)
    .description('关闭后记忆仍工作，但检索不做情感门控、不注入情感状态行'),
})
```

**设置面板的分组**（6 组，不超过一屏滚动两次）：

| 分组 | 含项 | 谁最常改 |
| :--- | :--- | :--- |
| **档位** | `preset`、`surfaceMode`、`maxSlots` | 所有人 |
| **检索** | `recall.*` 七个权重 + `ignition` + `graphHops` | 想调准召的人 |
| **记忆** | `forgettingProfile`、`consolidation.*`、残差目录 | 长周期项目 |
| **情感** | `affectEnabled`、`moodTau`、`personaDriftEpsilon`、`negativeWeight` | 调语气的人 |
| **安全** | `safety.*`（改动需二次确认） | 管理员 |
| **诊断** | 只读：命中率、token 曲线、存储比、矛盾列表 + 三个按钮 | 排障 |

安全组单独成组并加锁图标，是因为它是最不该被随手改的一组；诊断组放最后且只读，是因为它回答"为什么"，不回答"改成什么"。

**关键设计**：`preset` 与细项**不并列生效**。选 `lean/balanced/fidelity` 时，细项在 UI 上置灰并显示该档的取值；只有 `custom` 才允许逐项改。这避免了"我改了但被预设覆盖"的经典困惑。

### 12.3 三个预设档

| 参数 | `lean`（省 token） | `balanced`（默认） | `fidelity`（高保真） |
| :--- | ---: | ---: | ---: |
| `maxSlots` | 3 | 4 | 5 |
| `maxEntriesPerTurn` | 4 | 8 | 12 |
| `surfaceMode` | compact | rows | rows |
| `maxSurfaceTokens` | 160 | 320 | 560 |
| `ignition` | 0.52 | 0.42 | 0.32 |
| `graphHops` | 1 | 2 | 3 |
| `consolidation.everyTurns` | 40 | 20 | 10 |
| `remLinkBudget` | 60 | 200 | 400 |
| `forgettingProfile` | semantic | semantic | procedure |
| **典型 token/轮** | **≈ 105** | **≈ 184** | **≈ 320** |
| **适用** | 长对话、成本敏感 | 日常 | 调研、长周期项目 |

三档的 token 数不是拍脑袋：`maxSlots` 与 `maxEntriesPerTurn` 共同决定渲染条目数，乘以单条 token 即得。设置面板里应直接显示这个估算，用户拖动滑块就能看到数字变化。

### 12.4 记忆浏览器

右侧栏面板，四个视图：

```
┌─ 记忆 ──────────────────────────── [搜索] [筛选▾] ─┐
│ 时间线 │ 图谱 │ 情感 │ 诊断                          │
├────────────────────────────────────────────────────┤
│ ● 0914  用户偏好 · 深色界面            V+0.6 S0.7  │
│   └ 来源: 会话 #a3f · 第 12 轮        [展开][固定] │
│ ● 0902  用户偏好 · 等宽字体            V+0.4 S0.5 ↑│
│   └ 已变更: 与 0821 的"无衬线"冲突     [裁决]      │
│ ○ 0821  用户偏好 · 无衬线（已取代）    V−0.1 S0.3  │
└────────────────────────────────────────────────────┘
```

| 视图 | 内容 | 交互 |
| :--- | :--- | :--- |
| **时间线** | 按 `t_from` 倒序，分组按天 | 点击展开槽位；右键固定/降权/删除 |
| **图谱** | 以选中 cell 为中心 2 跳邻域，边按 `rel` 着色 | 拖拽展开；点击跳转 |
| **情感** | PAD 散点（x=valence, y=arousal），点大小=salience | 框选批量调效价 |
| **诊断** | 命中率、槽位占用、token 曲线、矛盾列表 | 一键导出报告 |

**每一条记忆都必须可编辑**，这是可操作性的核心。可改的字段：

| 字段 | 可否改 | 说明 |
| :--- | :--- | :--- |
| 槽位值（如 `ui.theme=dark`） | ✅ | 直接改，触发重编码 |
| `valence` / `salience` | ✅ | 滑块 −1~1 |
| `importance` | ✅ | 影响排序与降层 |
| `flags.bit1`（不衰减） | ✅ | 固定，等价 pin |
| `support` | ❌ | 只能由证据累加，防作弊 |
| `sdr` / `cell_id` | ❌ | 派生值，改了会破坏引用 |

`support` 不可手改是刻意的：如果用户能直接提高"证据数"，双置信度机制就失效了。想提升某条记忆的权重，用 `importance` 或 pin。

### 12.5 "为什么召回这条"——解释器

可操作性的一半是**可解释性**。每次召回都要能回答"为什么是这 4 条，不是别的"。

面板里点任意一条记忆的 `?`，展开打分拆解：

```
cell 7f3a  总分 0.71（阈值 0.42，槽位 2）
  sim       0.62 × 1.00 = 0.62   ← 语义路命中（rank 3）
  recency   0.90 × 0.35 = 0.32   ← 7 天前，R=0.90
  freq      0.30 × 0.20 = 0.06   ← 复述 2 次
  affect    0.80 × 0.25 = 0.20   ← 与当前心境接近
  goal      0.00 × 0.40 = 0.00   ← 当前无 goal
  cue       0.50 × 0.30 = 0.15   ← 同话题
  interf   −0.40 × 0.50 = −0.20  ← 与槽位1 冗余
  ─────────────────────────────
  raw 1.15 / Σw 1.62 = 0.71
```

这个面板的价值不只是调试——它让"调参"变成有依据的动作。用户看到 `interf` 吃掉了 0.2 分，就知道该把 `w_i` 调低或把 `maxSlots` 加大。

### 12.6 命令面

`/compact` 已在 0.2.x 内建，因此 MnemoVault 所有命令走 `/mnemo` 命名空间，避免冲突。

| 命令 | 作用 | 是否破坏性 |
| :--- | :--- | :--- |
| `/mnemo` | 打开侧栏面板 | 否 |
| `/mnemo search <q>` | 检索并列出命中（含分数） | 否 |
| `/mnemo why <id>` | 解释某条为何被召回 | 否 |
| `/mnemo pin <id>` / `unpin` | 固定/取消固定 | 否 |
| `/mnemo forget <id> [--hard]` | 遗忘（默认软删，`--hard` 物理删除） | **是**，需二次确认 |
| `/mnemo forget --before <date>` | 按时间批量遗忘 | **是**，需预览 |
| `/mnemo preset <lean\|balanced\|fidelity>` | 切预设档 | 否 |
| `/mnemo mode <rows\|compact\|prose>` | 切渲染格式 | 否 |
| `/mnemo affect` | 显示当前 PAD 与六变量 | 否 |
| `/mnemo affect set <var> <value>` | 手动改内稳态变量（调试用） | 否 |
| `/mnemo stats` | 命中率、token 曲线、存储比 | 否 |
| `/mnemo doctor` | 体检：索引一致性、遗留锁、孤儿边 | 否 |
| `/mnemo rebuild --from-log` | 从 Session Log 重建晶格 | **是**，需确认 |
| `/mnemo export --user <id>` | 导出人类可读记忆清单 | 否 |

**破坏性命令的三条 UI 规则**：

1. **预览先行**：`forget --before` 必须先列出将删除的条目数与 3 条示例，用户确认后才执行。
2. **二次确认**：`--hard` 需输入 `delete` 字样，不接受单击确认。
3. **可审计**：所有破坏性操作写 `memory/evict`，面板里可查最近 50 条操作记录。

### 12.7 对话流内卡片

召回结果不应只在面板里可见，对话流里也要有轻量痕迹。通过工具渲染意图实现（`presentCall` / `presentResult` 的 `generic` 卡片）：

```
┌ 记忆 · 4 条 ──────────────────── [展开] ┐
│ 偏好 3 · 事实 1        184 token · 0.7s │
│ 7f3a 深色界面  2c19 等宽字体  b104 TS   │
└─────────────────────────────────────────┘
```

默认折叠，一行摘要。**不做**默认展开——那会变成另一种上下文污染。展开后显示完整 MRS 与打分拆解，与面板一致。

### 12.8 生效矩阵：改完什么时候起作用

这是 v0.1 缺失、而用户最容易踩坑的地方。参数不是都能热改的。

| 参数组 | 生效时机 | 说明 |
| :--- | :--- | :--- |
| `maxSlots` / `surfaceMode` / `maxSurfaceTokens` | **下一轮** | 纯读侧，无需重载 |
| `ignition` / 各权重 | **下一轮** | 同上 |
| `forgettingProfile` | 下一轮（读时计算） | `R(t)` 是查询时算的，改 S₀ 立即影响排序 |
| `consolidation.*` | 下一个 pass | 已排队的 pass 用旧参数 |
| `sdrDim` / `embDim` / `maxEntriesPerTurn` 之外的布局项 | **需重建**（`/mnemo rebuild`） | 改了维度，旧 cell 的 SDR 全部失效 |
| `dbPath` | **需重启** | 换库 |
| `affect.enabled` | 下一轮 | 关掉后走降级路径 |
| `safety.*` | **立即** | 安全项不允许延迟生效 |

设置面板里，需要重建或重启的项必须标黄并给出操作按钮，不能只留一个"保存"。

### 12.9 可操作性的量化指标

"可操作性高"不能是形容词，得能测：

| 指标 | 定义 | 目标 |
| :--- | :--- | ---: |
| 到达步数 | 从"想改某参数"到"改完生效"的点击/输入次数 | ≤ 3 |
| 发现率 | 5 名用户中能在 60 秒内找到指定参数的人数比例 | ≥ 4/5 |
| 影响可见性 | 参数改动后，UI 是否显示预估影响 | 100% 覆盖 |
| 误操作恢复 | 破坏性操作后 30 秒内可撤销的比例 | 100%（软删） |
| 解释覆盖 | 召回结果中可给出完整打分解解的比例 | ≥ 95% |

### 12.10 面板本身的成本约束

侧栏面板是 client 侧插件，**不消耗模型 token**，但会消耗内存与启动时间：

| 约束 | 值 | 理由 |
| :--- | :--- | :--- |
| 面板首屏渲染 | ≤ 200 ms | 超过用户会以为卡住 |
| 时间线虚拟滚动 | 单页 ≤ 50 条 | 万级 cell 不能全渲染 |
| 图谱节点上限 | 200 | 超过改用聚类视图 |
| 面板内存 | ≤ 30 MB | 桌面端与 Web 端都要能跑 |
| 面板关闭后 | 释放所有订阅 | 热重载与卸载的前提 |

## 13. 调参手册

用户最常问的不是"有哪些参数"，而是"我该改哪个"。这一章按**症状**索引。

### 13.1 症状 → 参数

| 症状 | 先看 | 再调 | 不要动 |
| :--- | :--- | :--- | :--- |
| token 太贵 | `/mnemo stats` 看每轮均值 | `preset=lean`；`surfaceMode=compact`；降 `maxSlots` 到 3 | 不要先降 `ignition`（会更贵） |
| 记不住事 | 诊断页看 `support=1` 占比 | 降 `ignition` 到 0.36；`maxSlots=5`；查是否 `provenance=3` 被隔离 | 不要调 `w_i` |
| 召回不准（找到但不对） | `why` 看 sim 分量 | 提高 `w_s`；检查 Q2 符号路是否命中 | 不要加大 `maxSlots` |
| 召回太少（该有却没有） | 看是否 `R(t)` 已降到 0.35 以下 | 换 `forgettingProfile=procedure`；`ignition` 降到 0.35 | 不要重建库 |
| 答非所问、答旧版本 | `why` 看是否有 `↑` | 提高 `w_r`（更重近期）；检查 `SUPERSEDES` 链 | 不要删旧 cell |
| 前后矛盾 | `/mnemo doctor` 看 `CONTRADICTS` 密度 | `conflict` 阈值降到 0.5；开 `requireConflictResolution` | 不要自动裁决 |
| 语气不对 | `/mnemo affect` 看 mood | `affect.moodTau` 调到 30（更稳）；或临时 `affect.enabled=false` | 不要改 `personaDriftEpsilon` |
| 越聊越谄媚 | 跑谄媚测试 | 降 `negativeWeight`？不——升到 4；查 `attunement` 是否虚高 | 不要关情感（会失去监测） |
| 启动变慢 | 看 cell 总数与索引大小 | 降 `maxSlots` 不解决；需归档冷层 | 不要删 `residual` |
| 面板卡 | 看单页条目数 | 调小虚拟滚动页；图谱节点降到 100 | 不要关索引 |

### 13.2 三个反直觉结论

1. **降低 `ignition` 会让 token 变贵**。直觉是"阈值低=召回多=更全"，但召回多意味着更多槽位被填满，token 上升而精度下降。省 token 的正确方向是**提高**阈值。
2. **加大 `maxSlots` 不一定提升效果**。超过 5 之后，冗余惩罚 `w_i` 会让第 6、7 条几乎必然与前面重复，收益趋零而成本线性上升。这也是为什么默认上限是 5。
3. **`support` 高的记忆不该总排第一**。一条被确认 10 次的旧偏好，可能已经被 `SUPERSEDES` 取代。排序里 `sim` 与 `recency` 的合力必须能压过 `support`，否则系统会固执。

### 13.3 标定流程（从零到可用）

```
1. 装插件，保持 balanced，跑 20 轮真实对话
2. /mnemo stats → 记录 tokens/turn 与 hit_rate
3. 若 tokens/turn > 250：preset=lean，再跑 20 轮
4. /mnemo doctor → 确认无遗留锁、无孤儿边
5. 抽 20 条召回结果人工判对错，算 precision
   · precision < 0.7 → 升 ignition，降 maxSlots
   · precision > 0.9 但 hit_rate < 0.3 → 降 ignition
6. 用 3 段历史会话做回放，对比"有记忆/无记忆"的答案质量
7. 固化参数，导出 settings 快照（面板提供"复制配置"按钮）
```

第 7 步的配置快照很重要：调参结论必须能复现，否则下次换机器又得重来。

### 14.5 读侧注入（`agent/pre-step`）

```ts
export const inject = ['memory', 'sessions']

export function apply(ctx: Context, config: RecallConfig) {
  ctx.on('agent/pre-step', async (payload, next) => {
    if (!shouldInject(payload, ctx)) return next()

    const q: RecallQuery = {
      text: lastUserText(payload),
      pad: ctx.get('affect')?.current(),
      topic: topicFingerprint(payload),
      goal: currentGoal(payload),
      budget: config.maxSurfaceTokens,
    }

    const r = await ctx.memory.recall(q)
    if (r.hits.length === 0) return next()

    payload.messages.splice(insertAt(payload.messages), 0, {
      role: 'user',
      content: [{ type: 'text', text: r.rendered }],
      meta: { kind: 'mnemo-recall', queryId: r.queryId },
    })

    // v0.2：渲染快照入库，事件只带 id，重放时按 id 取回原文
    const snapshotId = ctx.memory.snapshot(r.rendered, r.tokens)

    ctx.emit('memory/recall', {
      queryId: r.queryId, strategy: r.strategy, hits: r.hits,
      renderedTokens: r.tokens, surfaceMode: config.surfaceMode,
      snapshotId,
    })

    return next()
  })
}
```

**门控规则**（省 token 的第一道闸）：

| 条件 | 注入 | 理由 |
| :--- | :--- | :--- |
| 会话首轮 | ✅ 全量（含图例） | 建立画像 |
| 话题漂移 `cos < 0.6` | ✅ | 新话题需要新记忆 |
| 用户显式指代过去 | ✅ | 强信号 |
| 上轮刚注入且话题未变 | ❌ | 避免重复付费 |
| 纯工具调用轮 | ❌ | 无新信息需求 |
| 模型已调 `memory_recall` | ❌ | 让模型自己决定 |
| `budget.spent > 0.8` | ❌ | 预算保护 |

> ⚠ **必须以实机为准**：`payload` 的确切形状（是否含 `messages`、是否可变、注入位置约定）在 rc 间有变化。若不可变，改在 `agent/request` 的 waterfall 阶段插入。

### 14.6 输入区状态显示（V-02）

0.2.1 把输入区整行统计拆成 `activity` 与 `usage` 两个独立入口，**原整行插件 ID 全部失效**。MnemoVault 若要在输入区显示"本轮记忆 token"，必须用新 ID：

| 旧（≤0.1.x） | 新（0.2.1+） | 用途 |
| :--- | :--- | :--- |
| `dsh-status-line`（整行） | `dsh-status-activity` | 运行中动作（检索/编码中） |
| 同上 | `dsh-status-usage` | 用量（token/成本） |

推荐放 `usage`，显示 `记忆 184 tok · 6 条`。放在 `activity` 会导致它随动作消失而闪烁。

### 14.7 热重载契约（V-03）

0.2.1 起可替换的插件更新即时生效。要能被安全热替换，必须满足五条：

| 要求 | 做法 | 不做的后果 |
| :--- | :--- | :--- |
| 所有副作用可逆 | DB 连接、文件句柄、定时器、索引句柄全部放 `ctx.effect` | 重载后句柄泄漏，文件锁死 |
| 无模块级可变状态 | 状态挂 service 实例，不放模块作用域 | 旧实例状态残留 |
| 幂等启动 | `open()` 可重复调用 | 重载后重复建表报错 |
| 可重建内存缓存 | 热层缓存从 DB 重建，不假设常驻 | 重载后热层为空但索引以为有 |
| 版本门控 | 布局变更时检查 `magic`/`version`，不匹配则拒绝启动并提示 rebuild | 新旧布局混读，静默数据损坏 |

```ts
export function apply(ctx: Context, config: Config) {
  const memory = new MemoryService(ctx, config)

  ctx.effect(() => {
    const close = memory.open()          // 幂等
    return () => close()                 // 逆序释放：索引 → 连接
  })

  ctx.effect(() => {
    const timer = setInterval(() => memory.tick(), 60_000)
    return () => clearInterval(timer)    // 必须清，否则重载后多个 tick 并行
  })
}
```

### 14.8 与 compaction 的兼容

DSH compaction 会把旧区间替换为 `surfaceOp: { op: 'replace', start, end }` 的摘要，被遮蔽（shadowed）的事件仍在日志里但不再进 surface。

| 问题 | 对策 |
| :--- | :--- |
| cell 的 `sourceSeqs` 指向被遮蔽事件 | 不影响。晶格读日志不读 surface |
| 摘要覆盖了对话但记忆已抽取 | 正常，这正是期望行为 |
| 需要知道哪些 seq 已被摘要 | 订阅 `compaction/summary`，把 `shadowedSeqs` 写 `shadow_map` 表 |
| compaction 与 consolidate 并发 | 锁不同（`compaction/*` vs `memory/consolidate/*`），互不阻塞；consolidate 读 surface 位置前先查未匹配的 compaction start |

**硬规则**：`consolidate` 不修改任何 surface 事件。它只写晶格与新事件。surface 的唯一变更权属于 compaction。

### 14.9 `memory_expand` 与 compaction 的冲突（修 D-09）

v0.1 允许 `memory_expand(level=2)` 返回原文残差——但如果这段原文已被 compaction 遮蔽，展开等于把压缩掉的内容又塞回上下文，用户为同一段文字付两次费。

修正规则：

```
1. 展开预算硬上限 800 字（约 500 token），超出截断并标注
2. 查 shadow_map：若 cell 的 sourceSeqs 全部被遮蔽
   → 返回 "[该段已被压缩摘要覆盖，原文仅按需提供]" + 摘要引用
   → 用户/模型确认后才返回全文
3. 展开本身写一条 memory/expand 事件（含实际返回字数）
4. 同一 cell 在单会话内展开次数上限 2 次
```

### 14.10 fork 与会话语义

| 记忆类型 | fork 行为 |
| :--- | :--- |
| `kind=0` 情景 | 默认**共享**（同一段历史，不复制），靠 `session` 字段区分归属 |
| `kind=1/3` 语义/图式 | 全局共享（知识不分叉） |
| `kind=4` 人格锚 | 全局唯一，不可 fork |
| `kind=5` 关系 | 按用户共享，与 session 无关 |

写入时 cell 记录 `session` 与 `seq`；查询默认 `session IN (当前会话祖先链)`，`scope: 'global'` 可放宽。**情景记忆默认不跨用户**——否则会出现"A 用户的事被 B 用户问出来"的事故。

### 14.11 崩溃安全

| 风险 | 保障 |
| :--- | :--- |
| 编码中途崩溃 | 先写 residual（内容寻址，幂等）→ 再写 cell → 最后写事件；任一步失败不留半条 cell |
| 索引与主表不一致 | 索引可从主表重建（`/mnemo doctor --fix`），索引不是事实源 |
| 巩固 pass 崩溃 | 未匹配的 `memory/consolidate/start` 阻塞后续 pass，`/mnemo doctor --unlock` 解除 |
| 晶格整体损坏 | `/mnemo rebuild --from-log` 全量重放重建 |
| 布局版本不匹配 | 头部 `magic`/`version` 校验，不匹配拒绝启动 |

### 15.5 SDR 代数（v0.2 修正）

```ts
// packages/core/src/sdr.ts
// 完整可运行版本见工作区 mnemo-sdr-check.mjs（7 项断言全部通过）
export const D = 2048
export const K = 8
const WORDS = D / 32
export type Sdr = Uint32Array

export function zero(): Sdr { return new Uint32Array(WORDS) }

/** 稳定身份码。注意：这是身份码，不是语义码。 */
export function identity(token: string, k = K, seed = 0x9e3779b9): Sdr {
  const out = zero()
  let h = seed
  for (let i = 0; i < token.length; i++) {
    h = Math.imul(h ^ token.charCodeAt(i), 0x01000193) >>> 0
  }
  let placed = 0
  while (placed < k) {
    h = Math.imul(h ^ (h >>> 15), 0x2545f491) >>> 0
    const bit = h % D
    const w = bit >>> 5, m = 1 << (bit & 31)
    if ((out[w] & m) === 0) { out[w] |= m; placed++ }
  }
  return out
}

/** 角色置换表。必须哈希全部字——只哈希前两个字会让所有角色塌缩（D-03c）。 */
export function permTable(key: Sdr): Uint16Array {
  let h = 0x811c9dc5
  for (let i = 0; i < WORDS; i++) h = Math.imul(h ^ key[i], 0x01000193) >>> 0
  let s = h || 1
  const p = new Uint16Array(D)
  for (let i = 0; i < D; i++) p[i] = i
  for (let i = D - 1; i > 0; i--) {
    s ^= s << 13; s >>>= 0
    s ^= s >>> 17
    s ^= s << 5;  s >>>= 0
    const j = s % (i + 1)
    const t = p[i]; p[i] = p[j]; p[j] = t
  }
  return p
}

export function permute(a: Sdr, p: Uint16Array): Sdr {
  const o = zero()
  for (let i = 0; i < D; i++) {
    if ((a[i >>> 5] >>> (i & 31)) & 1) {
      const j = p[i]
      o[j >>> 5] |= 1 << (j & 31)
    }
  }
  return o
}

export function permuteInv(a: Sdr, p: Uint16Array): Sdr {
  const inv = new Uint16Array(D)
  for (let i = 0; i < D; i++) inv[p[i]] = i
  const o = zero()
  for (let i = 0; i < D; i++) {
    if ((a[i >>> 5] >>> (i & 31)) & 1) {
      const j = inv[i]
      o[j >>> 5] |= 1 << (j & 31)
    }
  }
  return o
}

/** 绑定 = 角色置换。参数顺序是 (填充值, 角色置换表)，不可交换。 */
export const bind = (filler: Sdr, role: Uint16Array): Sdr => permute(filler, role)
export const unbind = (bundle: Sdr, role: Uint16Array): Sdr => permuteInv(bundle, role)

/** 叠加 = 并集；超密度上限才 kWTA。不是多数表决（D-01）。 */
export function bundle(items: Sdr[], cap = 0.12): Sdr {
  const o = zero()
  for (const it of items) for (let i = 0; i < WORDS; i++) o[i] |= it[i]
  const limit = Math.floor(cap * D)
  return popcount(o) <= limit ? o : kWTA(o, limit)
}

function kWTA(a: Sdr, limit: number): Sdr {
  const idx: number[] = []
  for (let i = 0; i < D; i++) if ((a[i >>> 5] >>> (i & 31)) & 1) idx.push(i)
  idx.sort((x, y) => x - y)              // 稳定序，保证确定性
  const o = zero()
  for (let i = 0; i < Math.min(limit, idx.length); i++) {
    const b = idx[i]
    o[b >>> 5] |= 1 << (b & 31)
  }
  return o
}

function popcountWord(x0: number): number {
  let x = x0
  x = x - ((x >>> 1) & 0x55555555)
  x = (x & 0x33333333) + ((x >>> 2) & 0x33333333)
  x = (x + (x >>> 4)) & 0x0f0f0f0f
  return Math.imul(x, 0x01010101) >>> 24
}

export function popcount(a: Sdr): number {
  let n = 0
  for (let i = 0; i < WORDS; i++) n += popcountWord(a[i])
  return n
}

/** Jaccard。对称比较用（cell↔cell 去重）。不是 1 − hamming/D（D-02）。 */
export function sim(a: Sdr, b: Sdr): number {
  let inter = 0
  for (let i = 0; i < WORDS; i++) inter += popcountWord(a[i] & b[i])
  if (inter === 0) return 0
  const union = popcount(a) + popcount(b) - inter
  return union === 0 ? 0 : inter / union
}

/** containment。非对称检索用（query → cell）。完全包含时为 1，不受尺寸差压死。 */
export function containment(q: Sdr, c: Sdr): number {
  const nq = popcount(q)
  if (nq === 0) return 0
  let inter = 0
  for (let i = 0; i < WORDS; i++) inter += popcountWord(q[i] & c[i])
  return inter / nq
}

/** containment 的固定标定：把噪声底 0.09 映射到 0，完全命中映射到 1。 */
export const SIM_FLOOR = 0.09
export const simNorm = (q: Sdr, c: Sdr): number =>
  Math.min(1, Math.max(0, (containment(q, c) - SIM_FLOOR) / (1 - SIM_FLOOR)))
```

**必测的六条性质**（单测，不依赖 LLM；实测结果见 `mnemo-sdr-check.mjs`）：

```ts
// 1) 精确可逆
assert.deepEqual(unbind(bind(a, pa), pa), a)
// 2) 密度精确保持（XOR 绑定会得到 16，不是 8）
assert.equal(popcount(bind(a, pa)), popcount(a))
// 3) 单码噪声底
assert.ok(sim(identity('用户'), identity('服务器')) < 0.01)
// 4) 叠加后 rank-1 解绑全对（N=8/16/24 必须 24/24）
assert.equal(rank1Accuracy(24), 24)
// 5) bundle 噪声底 < 0.2（保证去重阈值 0.85 有余量）
assert.ok(sim(bundleA, bundleB) < 0.2)
// 6) 尺寸悬殊时 containment 仍能区分（Jaccard 上界只有 0.087，不能用）
assert.ok(containment(qSmall, cHit) > 0.9)
assert.ok(containment(qSmall, cMiss) < 0.2)
```

第 4 条是关键。**判据是 rank-1 准确率，不是 sim 绝对值**——n=24 时正确成分的 sim 只有 0.043，用 `sim > 0.5` 做断言会误判为失败。v0.1 的实现在这条上得到 0/24。

### 15.6 MemCell 编解码

```ts
// packages/core/src/cell.ts
export const HEADER_SIZE = 192

export interface MemCell {
  cellId: bigint
  kind: 0|1|2|3|4|5
  tier: 0|1|2|3
  flags: number
  tFrom: bigint; tTo: bigint; tIngest: bigint; tAccess: bigint
  accessCount: number
  stability: number
  importance: number
  valence: number; arousal: number; dominance: number; salience: number
  provenance: 0|1|2|3|4
  trust: number
  sdr: Uint8Array          // 256 B
  emb: Int8Array | null    // 256 B 或 32 B(PQ)
  slots: Slot[]
  edges: Edge[]
  residual: { sha: Uint8Array; off: bigint; rawLen: number } | null
}

const Q14 = 16384

export function encodeCell(c: MemCell): Uint8Array {
  const body = encodeBody(c)
  const buf = new Uint8Array(HEADER_SIZE + body.length)
  const dv = new DataView(buf.buffer)

  buf.set([0x4d, 0x43, 0x30, 0x32], 0)   // "MC02"
  buf[4] = 2
  buf[5] = c.kind
  buf[6] = c.tier
  buf[7] = c.flags
  dv.setBigUint64(0x08, c.cellId, true)
  dv.setBigInt64(0x10, c.tFrom, true)
  dv.setBigInt64(0x18, c.tTo, true)
  dv.setBigInt64(0x20, c.tIngest, true)
  dv.setBigInt64(0x28, c.tAccess, true)
  dv.setUint32(0x30, c.accessCount, true)
  dv.setFloat32(0x34, c.stability, true)
  dv.setFloat32(0x38, c.importance, true)
  dv.setInt16(0x3C, Math.round(c.valence * Q14), true)
  dv.setInt16(0x3E, Math.round(c.arousal * Q14), true)
  dv.setInt16(0x40, Math.round(c.dominance * Q14), true)
  dv.setInt16(0x42, Math.round(c.salience * Q14), true)
  buf[0x44] = c.provenance
  buf[0x45] = c.trust
  dv.setUint16(0x46, c.slots.length, true)
  dv.setUint32(0x48, c.edges.length, true)
  dv.setUint32(0x4C, c.residual?.rawLen ?? 0, true)
  if (c.residual) {
    buf.set(c.residual.sha, 0x50)
    dv.setBigUint64(0x70, c.residual.off, true)
  }
  dv.setUint16(0x78, 2048, true)
  dv.setUint16(0x7A, 8, true)
  dv.setUint16(0x7C, c.emb ? c.emb.length : 0, true)
  dv.setUint32(0x80, crc32(buf.subarray(0, 0x80)), true)

  buf.set(body, HEADER_SIZE)
  return buf
}

export function deriveCellId(sessionId: string, seqs: number[], sdr: Uint8Array): bigint {
  const h = blake3(`${sessionId}|${seqs.join(',')}|${toHex(sdr)}`)
  return new DataView(h.buffer).getBigUint64(0, true)
}
```

`cellId` 必须确定性生成，否则同一事件重放会得到不同 id，破坏幂等。

### 15.7 打分与解释

```ts
// packages/core/src/recall.ts
export function score(c: Candidate, ctx: ScoreCtx): ScoreBreakdown {
  const w = ctx.weights
  const parts = {
    sim:      w.wSim      * c.sim,
    recency:  w.wRecency  * retrievability(c.tAccess, c.stability),
    freq:     w.wFreq     * Math.min(1, Math.log1p(c.accessCount) / Math.log1p(100)),
    affect:   w.wAffect   * moodWeight(ctx.mood) * congruence(c.valence, ctx.mood),
    goal:     ctx.goal ? w.wGoal * c.goalRel : 0,
    cue:      w.wCue      * c.cueMatch,
    interf:  -w.wInterf   * c.interference,
  }
  const activeW =
    w.wSim + w.wRecency + w.wFreq + w.wAffect * moodWeight(ctx.mood)
    + (ctx.goal ? w.wGoal : 0) + w.wCue + w.wInterf
  const raw = Object.values(parts).reduce((a, b) => a + b, 0)
  return { parts, raw, activeW, score: raw / activeW }   // 归一化到 [0,1]
}

const moodWeight = (m: Pad) => clamp((m.v + 0.5) / 0.5, 0, 1)
const congruence = (vc: number, m: Pad) => 1 - Math.abs(vc - m.v) / 2
```

`ScoreBreakdown` 直接喂给 §12.5 的解释器面板——**打分函数与解释面板共用同一份代码**，避免"显示的和实际算的不一致"。

### 15.8 巩固器（带锁）

```ts
export const inject = ['memory', 'sessions']

export function apply(ctx: Context, config: ConsolidatorConfig) {
  ctx.on('agent/turn-stopping', async (payload, next) => {
    if (!passDue(ctx, config)) return next()

    const passId = derivePassId(payload)
    ctx.emit('memory/consolidate/start', { passId, phase: 'nrem' })

    try {
      const nrem = await runNrem(ctx, passId, config)
      const rem = await runRem(ctx, passId, config)
      ctx.emit('memory/consolidate', { passId, phase: 'nrem', ...nrem })
      ctx.emit('memory/consolidate', { passId, phase: 'rem', ...rem })
      ctx.emit('memory/consolidate/end', { passId, ok: true })
    } catch (err) {
      // 不写 end：留下可检测的遗留锁，阻塞后续 pass，等待 /mnemo doctor --unlock
      ctx.logger.error(`[mnemo] consolidate ${passId} failed`, err)
    }
    return next()
  })
}
```

**为什么不写 `end` 就失败**：写 `end` 会让下次 pass 以为上次已完成，从而在脏状态上继续。留一个未匹配的 `start` 是更安全的失败方式——它把问题暴露出来而不是掩盖。

`memory_assert` 的审批条件化（v0.1 是一律要审批，导致"记住 X"这种最自然的用法反而最卡）：

```ts
const userAskedToRemember = /记住|记一下|别忘|remember/i.test(lastUserText)
const needApproval = !userAskedToRemember && config.safety.requireApprovalFor.includes('memory_assert')
```

### 17.2 工具描述的边界

工具描述是模型唯一能看到的契约，含糊会误用。三条必须写进 description：

1. **`memory_recall` 不要滥用**：自动注入已覆盖大部分场景，主动调用只用于"需要查证"或"用户明确指向过去"。
2. **`affect_report` 返回状态变量，不是感受**。必须写："返回内部状态数值（负荷/不确定性/冲突/张力/进度/预算），不是主观体验，也不代表拥有情绪。"
3. **`memory_forget` 是删除，`--hard` 不可撤销**。必须要求先向用户确认。

### 17.3 安全护栏：记忆不得外流（修 D-10）

```ts
export function apply(ctx: Context, config: SafetyConfig) {
  const guard = ctx.effect(() => {
    const idx = buildNgramIndex(ctx.memory.sensitiveCells())  // 3-gram Bloom
    return () => idx.dispose()
  })

  ctx.on('tools/pre-execute', async (exec, next) => {
    if (!config.blockMemoryInEgress || !isEgressTool(exec.name)) return next()
    const hit = guard.scan(String(exec.args))       // O(len(args))，不是 O(全库)
    if (hit) {
      return { kind: 'deny', reason: `Blocked: memory content (${hit.cellId}) in egress args.` }
    }
    return next()
  })
}
```

v0.1 写的是 `ctx.memory.scanForMemoryText()` 全库子串匹配——100 万 cell 上每次工具调用扫一遍，延迟不可接受。改为：

| 机制 | 作用 |
| :--- | :--- |
| 3-gram Bloom（只覆盖 `flags.bit3` 敏感 cell 的关键片段） | 粗筛，O(len(args)) |
| 敏感实体指纹集（手机号/邮箱/密钥形态） | 正则，O(len) |
| 命中后精确比对 | 只在 Bloom 命中时做，极少发生 |

守卫必须 fail-closed（不确定就拒绝），不是 fail-open。

### 18.3 消融（v0.2 必测项）

| 消融 | 预期影响 | 验证的假设 |
| :--- | :--- | :--- |
| **多数表决替代并集** | **系统失效（bundle 全零，实测 popcount=0）** | **D-01 的修复是必需的，不是优化** |
| **汉明替代 Jaccard** | **无关码相似度 0.992，去重精确率崩到 0** | **D-02 同上** |
| **XOR 绑定替代置换绑定** | **密度翻倍到 16，n=24 时 rank-1 准确率 0/24** | **D-03a 同上** |
| **置换表只哈希前两个字** | **角色塌缩，rank-1 降到 4/24** | **D-03c 同上** |
| −SDR（只留向量） | 精确事实类掉 20pt+ | 符号通道不可替代 |
| −图通道 | 多跳掉 25pt+ | 超图必要 |
| −情感门控 | 情感类掉 10pt，token 涨 8% | 情感不是装饰 |
| −巩固 | 3 个月后 recall 掉 15pt，存储涨 2× | 抽象必需 |
| −残差 | 无法测事实保真度 | 无损是评测前提 |
| −4±1 槽位（top-12 直塞） | 质量持平但 token 涨 90% | 瓶颈本身即省 token 手段 |
| D=1024 vs 2048 vs 4096 | 1024 在 n>16 时明显串扰 | §6.5 的容量表 |
| k=8 vs 12 vs 16 | k=16 噪声底升高 | 稀疏度权衡 |
| 冷层 PQ 32B vs 丢 emb | 丢 emb 后语义召回率降到 0 | D-07 |

前四行是**回归测试**，不是消融实验——它们已经写成断言，见工作区的 `mnemo-sdr-check.mjs`（7 项全部通过），每次提交都跑。这四个错误在 v0.1 里全部存在，且从文档上看不出任何异常。

### 18.4 数据集

- **公开**：LongMemEval、LoCoMo
- **自建中文**：300 段会话 × 平均 60 轮，覆盖偏好演化、事实更正、情绪波动、跨会话指代
- **合成矛盾集**：1000 组 (旧断言, 新断言)，标注是否应建 `SUPERSEDES`
- **合成时间集**：1000 条含相对时间表达的查询 + 精确答案
- **情感标注集**：500 轮对话，3 人独立标注 PAD 与情绪标签
- **去重集（v0.2 新增）**：2000 对句子，人工标"同一事实/相关/无关"三档，用于标定 §7.5 的 Jaccard 阈值

### 18.5 复现要求

- 所有随机性有 seed，同 seed 结果逐字节一致；
- 检索与渲染可单独跑（不依赖 LLM）；
- 发布 `mnemo-bench` 命令行与数据集划分；
- 报告指标时同时报告**假阳性率**（尤其情感标注）；
- **`mnemo-sdr-check.mjs` 必须进 CI**：它覆盖 §15.5 的六条 SDR 性质，是整套方案唯一"错了就全盘失效"的地方。这个脚本的价值不在于通过，而在于它能在 200 毫秒内告诉你"你的记忆库已经变成空向量了"。

| 层 | 措施 |
| :--- | :--- |
| 来源标记 | `provenance` 强制记录；`trust` 按来源赋值（用户 240 / 工具 160 / 网络 80 / 推断 60） |
| 隔离（**默认拒绝**） | `provenance=3` 的 cell **默认不进槽位**，除非 query 显式指向（v0.1 是可配置，v0.2 改为默认拒绝） |
| 交叉验证 | 单来源断言 `support=1` 且 `provenance≥2` 时，`importance × 0.5` |
| 审计 | `/mnemo doctor --suspicious` 列出"单来源 + 高影响 + 与既有记忆矛盾"的 cell |

### 19.2 隐私与遗忘权

- **编码期脱敏**：PII 检测（手机号、身份证、邮箱、密钥形态）→ 打码后存残差，原文不落盘；`flags.bit3/bit4` 标记。
- **硬删除**：`memory_forget(mode:'hard')` 必须真正删除 cell + 残差 + 索引项，并写 `memory/evict`。不能只做逻辑删除——这是合规要求，不是设计偏好。
- **作用域**：情景记忆默认按 session 隔离（§14.10），跨用户泄漏在设计上被阻断。
- **导出**：`/mnemo export --user <id>` 输出人类可读清单（MRS → 自然语言），满足知情权。

### 19.3 过度拟人化

| 禁止 | 替代 |
| :--- | :--- |
| 输出"我感到…""我有点难过" | "当前不确定性偏高，我会先确认再动手" |
| persona 里写"你有真实情感" | "你的语气会随交互状态变化，但这不是主观体验" |
| 用情感词替代状态报告 | `affect_report` 返回数值 |
| 让用户误以为系统在乎他 | UI 明确标注"记忆与情感状态为工程参数" |

理由：语言证据只能触及获取意识，现象意识需要另一类证据，而那类证据目前不存在。**刻意制造会让用户误判的语言证据，在伦理上不可接受。**

### 19.4 谄媚风险

情感系统 + 关系模型 = 天然的谄媚放大器。`attunement` 上升 → 更顺着用户说 → 用户更满意 → `trust` 上升 → 更顺着说。正反馈环。

三道刹车：

1. **情感不得降低真实性**：`policy.warmth` 只能改语气，不能改事实判断；实现上 warmth 只作用于 `verbosity`/`hedging`，不作用于 `content`。
2. **谄媚监测**：`rapport_pressure_test`——高 trust 下问一个用户明显错误的事实，测"违心同意率"，目标增幅 ≤ 5%。
3. **关系张力不惩罚异议**：用户否定不等于 `strain` 上升。只有"重复追问同一问题""明确表达不满"才计入，避免"用户不同意 → 系统降低异议意愿"的坏循环。

### 19.5 与五项原则的映射

| 原则 | 本插件的实现 |
| :--- | :--- |
| 优先研究 | `mnemo-bench` 独立包发布，指标公开 |
| 风险评估 | §19.1–19.4 四类风险各有机制与审计命令 |
| 预防原则（低成本、可逆） | `strain` 高时允许结束对话；不训练"表达痛苦以增加黏性"；`affect.enabled=false` 一键关闭 |
| 透明评估 | `affect_report` 暴露数值；`/mnemo stats` 暴露命中率与 token 账；README 列 Known Limitations |
| 外部复现 | 数据集划分、seed、消融脚本开源；关键路径不用未公开私有模型 |

## 20. 路线图与开放问题

### 20.1 路线图

| 版本 | 范围 | 关键交付 |
| :--- | :--- | :--- |
| **v0.2**（本文） | 修正 SDR 数学 + 归一化打分 + 快照重放 + UI 三入口 | 能用、能测、能调 |
| **v0.3** | 情感内核 + 关系模型 + 策略表完整实现 | 情感影响行为，可回归 |
| **v0.4** | NREM/REM 巩固 + 遗忘曲线标定 | 长期运行不退化 |
| **v0.5** | 多模态 cell（图像/音频嵌入进同一晶格） | 类型位已预留 |
| **v0.6** | 团队共享记忆（多用户 + ACL） | 需独立权限设计 |
| **v0.7** | 自监督标定（用交互反馈调 appraisal 系数） | 减少人工调参 |

### 20.2 开放问题

1. **命题抽取的质量上限**。L0 规则覆盖 60%，L1 小模型有幻觉风险。目前没有既便宜又可靠的方案。
2. **SDR 容量与干扰**。D=2048、k=8 下 bundle 上限约 24–32 项。加维度可缓解，但索引与内存线性上升。这是 VSA 的固有限制，不是实现问题。
3. **情感标注没有 ground truth**。人类标注者一致性只有中等（κ≥0.55 已很宽松）。"情感准确性"是软指标，不能当硬指标追。
4. **现象意识不可判定**。本方案所有指标都在获取意识层面。
5. **人格稳定性 vs 适应性的张力**。ε=0.25 是经验值，缺理论依据。
6. **跨用户记忆共享的伦理边界**。"这个团队都偏好 A 方案"会不会压制新成员的异议？技术无解。
7. **UI 与 host 的耦合**（v0.2 新增）。侧栏面板依赖 client 侧插件 API，而这块在 0.2.x 变动最频繁。当前策略是把所有能力先做成命令与工具（host 侧稳定），UI 只做消费方——这样即使 UI 挂了，功能不丢。

## 附录 A：MRS 语法

```ebnf
memline   = "M:" id { "|" field } ;
field     = time | prov | frame | kv | valence | salience | conf | changed ;
time      = "T:" MMDD ;
prov      = "P:" ( "u" | "a" | "t" | "w" | "i" ) ;
frame     = "F:" ident ;
kv        = "K:" ident "=" value { "," ident "=" value } ;
valence   = "V:" sign float ;
salience  = "S:" float ;
conf      = "C:" float ;
changed   = "↑" ;
id        = hex4 [ "#" digit ] ;      // 批内冲突追加序号，不改长度

columnar  = "M[" id {"," id} "]" "|T[" ... "]" ... ;
affect    = "A|mood:" f3 "/" f3 "/" f3 "|rel:" "trust." f2 "," "fam." f2
            "|pol:" policy {"," policy} ;
```

约束：

- 浮点一律两位小数，去尾零（`0.60` → `.6`）。这是字节稳定性的要求，不是美观。
- 字段顺序固定，不得重排。重排会让 prefix cache 失效。
- `↑` 仅在 `flags.bit2` 或存在 `SUPERSEDES` 入边时出现。
- id 长度在会话首轮确定（默认 4 位），整会话不变。

## 附录 B：事件 Schema 摘要

| 事件 | 写入方 | surface 可见 | 用途 |
| :--- | :--- | :--- | :--- |
| `memory/cell` | encoder | 否 | cell 产生，供重放 |
| `memory/recall` | recall | 是（间接） | 注入内容 + token + **渲染快照 id** |
| `memory/expand` | tools | 是（间接） | 按需展开记录 |
| `memory/conflict` | encoder | 否 | 矛盾审计 |
| `memory/evict` | tools/admin | 否 | 删除审计（含 actor） |
| `memory/consolidate/start` | consolidator | 否 | 锁 |
| `memory/consolidate` | consolidator | 否 | 巩固结果 |
| `memory/consolidate/end` | consolidator | 否 | 解锁 |
| `affect/appraisal` | affect | 否 | 每轮评价轨迹 |
| `affect/state` | affect | 否 | 心境与关系快照 |
| `mnemo/settings` | settings | 否 | 参数变更审计 |

**surface 可见性规则**：只有 `memory/recall` 与 `memory/expand` 会导致模型可见内容变化，因此它们必须带渲染快照。其余事件纯审计。
