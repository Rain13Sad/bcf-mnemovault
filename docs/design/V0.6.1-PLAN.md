> 规模：73 源文件 / 22.9k 行 / **265 测试**（+38）/ 11 包 / 26 命令

## §0 一句话

v0.6.0 的架构是对的，但它有两条**承诺与实现背离**：价格闸只报告不裁剪、模型画像在
最常见的写法上就 miss。这一版把它们连同三条「悄悄做错」一起修掉，并且**改了测试的写法**——
从"断言报告字段"改成"断言行为"。

## §2 与审计稿的一处分歧：F8 不该用 `expandEmb`

审计稿说 `project3` 没有展开冷层 32 维向量（注释承诺了但代码是 `Math.min`），
建议改成 `expandEmb(emb, dim)`。我按建议改了，然后**实测推翻了它**：

| 方案 | 12 条真实记忆的平均漂移 |
| :--- | ---: |
| 零填充（v0.6.0 的实际行为） | **0.031** |
| `expandEmb`（审计稿的建议） | **0.467** |

原因：`pq32()` 是 `pq4()` 之后取**前 32 个 nibble**，也就是"前 32 维的 4 bit 量化"，
它的忠实逆变换是**按下标放回前 32 位**。而 `expandEmb` 的 32 维分支按
"8 个子向量 × 4 字节"铺开——那是另一种解释，展开后反而把向量打散。

所以最终保留零填充，但做了三件事：把错注释改成事实、在代码里写下这组实测数字、
加一条 `v061-starmap` 的反例断言（谁改回 `expandEmb` 就会红）。

> 顺带记一条待办：打分路径用的确实是 `expandEmb`，与星图的解释不一致。
> 统一两者会改变召回分数，属于独立议题，进 v0.7。

## §3 刻意不做的：F3 的运行时改造

审计稿把"token 口径下沉到 core"排在 P1。本版**只做了上报，没改行为**，理由：

1. 改口径会让 `maxSurfaceTokens=320` 装进更多条目 → 召回结果变化 → 需要重跑全部质量指标；
   补丁版不该动召回行为。
2. 实测本 fixture 上高估只有 **10%**（116.9 → 105.4），不是审计稿在纯中文散文上测到的 45%。
   这个差距值得披露，但不值得为它承担召回回归风险。

所以 `bench.json` 现在同时给两个数：

```
tokensPerTurn            116.853   ← 启发式上界（CI 门槛仍用它，口径不变）
tokensPerTurnCalibrated  105.382   ← DeepSeek cjk-ratio 口径
```

README 改为**两个都写**，并注明"纯中文散文可高估约 45%"。

## §4 只做了一半的：F11

引擎构造时从 `memory.padSnapshot()` 取心境初值，解决"重启后引擎从 0 开始、面板显示 0.6"。
但**没有**把引擎心境写回 affect 包——那需要一条"引擎 → affect"的写路径，
而 affect 是可选包，引擎不该依赖它。

现状写进限制清单：引擎心境是**会话内状态 + 重启时从 affect 快照播种**。
完整的双向同步留给 v0.7（那时才会讨论"谁是心境的唯一真相"）。

## §5 测试策略的改动（这一版最重要的一条纪律）

v0.6.0 的 F1 之所以漏过去，是因为测试断言的是**报告字段**：

```js
assert.equal(gated.fits, false)              // 字段
assert.ok(gated.reasons.some(...'价格'))      // 字段
```

而 `rows` 一条没少。这一版把纪律写进测试文件头：

> **凡 `reasons` 里写了"按 X 裁剪"，就必须有一条断言证明 X 真的变了。**

于是新增的断言都是行为量：`rows`、`cost`、`droppedByBudget`、`space`、`cursor`。
另外补了 `suppressed` 字段——`fits` 只回答"输出在不在限制内"（空输出当然在），
调用方真正想知道的是"这次是不是被预算压掉了"。
