# MnemoVault v0.4.0 设计与实施计划

> 输入：`mnemovault-v0.4.0-增强设计方案.md`（下称「增强方案」）、`人类大脑记忆功能的表现与原理.md`（下称「记忆原理」）、`AI意识与情感的神经基础与工程路径.md`（下称「意识报告」）
> 基线：v0.3.1（115 个测试全绿，MC03 布局，六页签面板）
> 目标：**一次可发布、可回归、可解释的架构升级**，而不是把 12 周的四阶段一次性塞进一个版本号

---

## 0. 先说结论：v0.4.0 做哪一半

增强方案给出的是 M1–M4 共 12 周的完整路线。v0.4.0 的取舍原则只有一条：
**先做"能改变行为、能被断言"的部分，后做"能画出来但改不了决策"的部分。**

| 增强方案的里程碑 | v0.4.0 | 理由 |
| :--- | :--- | :--- |
| **M1 保留度重构** | ✅ 全部 | 直接回应用户诉求「删除不能只看时间」。ACT-R + 七因子 + 六档 + 六闸，全是纯函数，可回归 |
| **M2 类脑网络（DG/CA3/STDP）** | ⏸ 推迟 | 需要重训 SDR 空间与边权语义，会破坏 bench 基线。v0.4 只取其中**神经调制四信号**（纯增益，不改拓扑） |
| **M3 情感四层 + 不漠视** | ✅ 核心部分 | OCC 分类器 + 情绪事件状态机 + 三条硬规则。这是"不漠视"的机制保证，且纯函数可测 |
| **M4 动机 + 议程 + 神经可视化** | ⏸ 推迟 | A3 自主层涉及风险分级授权，是产品决策而非纯技术；神经三视图需要确定性布局引擎，工作量超过本次预算 |
| 增强方案未列：**面板横屏化** | ✅ 新增 | 用户明确提出。侧栏 300–420 px 的纵向面板在电脑上浪费了 2/3 屏宽 |

**一句话**：v0.4.0 = 保留度内核 + 情感事件机 + 横屏面板 + 存储/性能修复。v0.5 再上 CA3 与自主议程。

## 1. 三份文档 → 可执行条款的映射

### 1.1 从「记忆原理」拿到什么

| 文档结论 | 落到代码 |
| :--- | :--- |
| 遗忘曲线先快后慢，但**频率与近因统一在 ACT-R 激活里**（B_i = ln Σ t_j^−d） | `retention.ts: actrActivation()`。替代 `forgetting.ts` 里只看 `tAccess` 的判据 |
| 睡眠的三重耦合（SO–SS–SPW-R）与**稳态突触下调按比例而非按绝对值** | 巩固期仍用乘性降权（已有），但**被标记的边豁免**——v0.4 只落"情感记忆不参与降权"这一条可验证的部分 |
| 再巩固：提取使记忆重新可塑，**带着情绪回忆会记得更牢，被纠正过的记忆会被改写** | `reconsolidation.ts: onRetrieved()`，接在 `recall()` 的命中路径上 |
| 情绪记忆的强度不随时间线性衰减，杏仁核门控提高编码增益 | `retention.ts` 的 `affectIntensity` 权重在 fidelity 档最高；`FLAG.emotional` 走逆衰减与周年加成 |
| 工作记忆容量 4±1，且**容量是稀缺资源**（Cowan 修正 Miller） | 已有 `WorkingSet(16)` 与 4 槽竞争，v0.4 不动；但面板把"槽位占用"显式化 |

### 1.2 从「意识报告」拿到什么

| 文档结论 | 落到代码 |
| :--- | :--- |
| 获取意识（access）可工程化，现象意识（phenomenal）无交付路径 | 全部新增能力都标注为「状态数值」，`affect_report` 的免责声明保留并加强 |
| 全局工作空间要求**有限容量 + 竞争抑制**，而 LLM 的上下文是"大记事本" | 保留 4 槽竞争与 `ignition` 门控；新增"未平复情绪占独立 1 槽"，即**绕过竞争的保留通道**（H2HTalk 的 Secure Attachment 等价物） |
| 元认知：系统不能可靠地基于自身不确定性行动 | `neuromod.ts` 的 CORT/NE 信号进入检索锐度与策略，使"不确定时收窄"成为默认行为 |
| 情绪建构论四步：身体变化 → 感知 → 结合经验解释 → 情绪出现 | 情感管线已经是这个顺序；v0.4 把第三步（**经验解释**）显式化为 OCC 分类器 |
| 假阴性代价远高于假阳性 → 预防原则 | 情绪事件"未回应不衰减"，且**物理删除永不自动执行**——两处都是低成本可逆的预防措施 |

### 1.3 对标项目的取舍

| 项目 | 它做对了什么 | 我们抄什么 | 我们不抄什么 |
| :--- | :--- | :--- | :--- |
| **Mem0** | 提取式记忆 + 增量更新，工程极简 | 「合并优先于新增」的写入策略（已有） | 纯向量检索，没有时间推理 |
| **Zep / Graphiti** | 双时态（事件时间 vs 事务时间） | 已有 `tInvalid`；v0.4 让保留度同时看两侧 | 图数据库依赖 |
| **Letta (MemGPT)** | core / archival / recall 三层 + 自编辑 | 六档处置的**分层语义**（不是新表，是策略） | 让模型自己改记忆（风险不可控） |
| **A-MEM** | 记忆之间自动建链、动态演化 | 已有 `coactivate`；v0.4 给它加"降权"而不是只增 | 每轮 LLM 调用 |
| **Generative Agents** | 反思（reflection）产生洞察 | 推迟到 v0.5（Agenda） | 每日全量重跑 |
| **SleepGate** | 睡眠期选择性重放 | 推迟（需要 SWR 重放选择器） | — |
| **H2HTalk-SAP** | 情感轴与关系轴分离；去掉安全基地模块后违规涨 10 倍 | **情绪事件独立状态机 + 强制关怀槽** | 依赖大模型做安全判定 |

## 2. 模块设计

### 2.1 `packages/core/src/retention.ts`（新增，纯函数）

**ACT-R 激活**（用现有字段近似完整痕迹史）：

```
B = ln( Σ_{j=1..n} (t_now − t_j)^(−d) ),  d = 0.5
```

库里只存 `accessCount / tAccess / tIngest`，没有每次提取的时间戳。近似方式：
把 n 次提取视为在 `[tIngest, tAccess]` 上均匀分布，逐项求和。
`n = 1` 时退化为单项，与真实定义完全一致；`n` 大时误差方向已知（低估近期项），
因此再用 `tAccess` 单独补一项权重 0.5 修正近因。

**七因子加权**（默认权重按 lean / balanced / fidelity 三档）：

| 因子 | 来源 | 语义 |
| :--- | :--- | :--- |
| activation | ACT-R 归一化 | 频率 + 近因 |
| importance | `cell.importance` | 编码自评 |
| affectIntensity | `max(|v|, a, salience)` | 情绪强度 |
| connectivity | `log1p(degree)/log1p(maxDegree)` | 图枢纽度 |
| narrativeRole | kind=6 或 `FLAG.milestone` | 叙事角色 |
| userAffinity | pinned / 用户一手 / 被确认过 | 用户锚定 |
| spacing | 间隔效应 | 分散复习加成 |
| −redundancy | 与最近邻的 Jaccard | 冗余惩罚 |

`retentionScore()` 输出 0..1（sigmoid），`disposition()` 输出 P5..P1。

**六道删除闸** `protectedFromDeletion()`：
pinned / 情感记忆 / 人格锚 / 关系里程碑 / 用户亲口一手事实（trust ≥ 240 且 provenance=0）/ 版本链环节 / 仍被引用。
命中任意一条 → 不参与任何自动降档（降档可以，物理删除不行）。

**物理删除只由用户显式发起**，`demoteDue()` 最高只到 P1 墓碑（tier=3）。

### 2.2 `packages/core/src/reconsolidation.ts`（新增）

```
dS        = reinforce(S, R, Δt) − S            // 测试效应
dConf     = plastic ? −0.08·predErr : +0.02     // 被纠正 → 记忆变软
dValence  = 0.05·moodCongruence·(1−|v|)         // 心境一致性改写
labile    = max(0.05, 1/(1+ln(1+accessCount)))  // 反复提取后硬化
```

返回 `{ dStability, dConfidence, dValence, plastic, labile, notes }`，由 `recall()` 应用。

### 2.3 `packages/core/src/neuromod.ts`（新增）

四信号全部是已有量的纯函数，**不新增模型调用**：

| 信号 | 输入 | 输出作用 |
| :--- | :--- | :--- |
| DA δ | 新输入与上轮查询的余弦距离 | 编码增益、边标记 |
| ACh | 新实体占比 | 高 → 编码模式（图跳数 −1）；低 → 检索模式 |
| NE | arousal | 检索锐度（温度） |
| CORT | load + conflict | 高应激 → 收窄为 exploit |

v0.4 只把 DA 用于 `ingest` 的 importance 初值提示、ACh/NE 用于 `recall` 的图跳数与候选池宽度。
**不改打分公式**，避免破坏 bench 基线。

### 2.4 `packages/core/src/lifecycle.ts`（新增）

- `ConsolidationOutcome` 类型（abstracted / merged / demoted）
- `shouldAbstract(group)`：≥3 条情景 + 同 (AGENT, PRED) 骨架 + 同 topic + 跨度 > 1 天
- `nextTier(current, score, protectedReason)`：六档 → tier 的纯映射

### 2.5 `packages/affect/src/episode.ts`（新增）

- `classifyEmotion(appraisal)`：OCC 22 类，纯函数，不调 LLM
- `EmotionEpisode` 五态：`open → acknowledged → attended → resolved | dormant`
- `decayEpisode()`：**open 状态强度只增不减**（`peak + 0.05·ln(1+dt/H)`）
- `neglectQueue()`：`status ∈ {open, acknowledged}` 且强度 > 0.25，独立高优先槽
- `episodeLine()`：渲染成「⚠ 未平复：3 天前他说…」

### 2.6 存储与性能

| 问题 | 修法 |
| :--- | :--- |
| `resolveByPrefix` 每条边一次全表扫描 | `Store.findByPrefix()` + `CREATE INDEX idx_cells_prefix ON cells(substr(cell_id,9))`（低 32 位 = 末 8 位 hex） |
| 面板每次召回重建全量快照 | 已有 400 ms 节流；v0.4 让 `retention` 只算前 120 条 |
| `demoteDue` 每条都写库 | 只在 tier 真的变化时写 |

### 2.7 面板横屏化

```
┌──────────────┬─────────────────────────────────────────────┐
│ 长期记忆      │  页头：库路径 · 计数 · 刷新                    │
│ ───────────  │ ─────────────────────────────────────────── │
│ ● 记忆总览    │                                             │
│   记忆检索    │            内容区（宽屏双列）                  │
│   记忆整理    │                                             │
│   保留度  NEW │                                             │
│   收件箱      │                                             │
│   情感状态    │                                             │
│   设置        │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

- 用 **container query**（`@container (min-width: 760px)`）而不是 viewport media query——
  面板可能被塞进侧栏、也可能全屏，判据必须是**容器自身宽度**
- 窄于 760 px 自动回落为顶部页签（保留 v0.3 的可用性）
- 新增「保留度」页签：六档分布条 + 七因子堆叠条 + 四信号仪表 + 再巩固日志

## 4. 明确不做（诚实清单）

1. **CA3 自联想网络与 STDP**：会改边权语义，bench 的 Recall@8/MRR 需要重新标定基线，v0.5 单独做。
2. **Agenda 自主议程与 T0/T1/T2 授权**：涉及"它能自己做什么"的产品边界，需要用户参与决策。
3. **神经三视图（拓扑/栅格/场电位）**：需要服务端确定性布局引擎，先做保留度视图。
4. **现象意识相关表述**：维持项目立场——只做获取意识层的状态建模，不宣称主观体验。
5. **MC04 布局**：`retention_score` 暂不物化到列，10 万级规模下再引入（当前是 O(n) 现算 + 面板只算前 120 条）。
