# MnemoVault v0.5.0 实施方案：让决策链真的会出手

> 输入：`MnemoVault-v0.5.0更新计划.md`（P0/P1/P2 清单）、`MnemoVault-v0.4.0删除决策链路详解.md`（逐层源码拆解）、v0.4 发布说明与设计文档
> 基线：v0.4.0（`d34db42`，135 测试）
> 定位：**决策层正确性 + 发布工程收尾**。存储布局（MC03）与性能常数因子不动。

---

## 0. 一句话

v0.4 让系统**会算**保留度；v0.5 让算出来的数**真的有用**。

v0.4 的三个缺陷叠加起来，实际行为是：**对用户说过的话——不删、不归档、不降档，无论多琐碎、多过时、多重复。**
实测：10 条用户陈述，`demoteDue` 移动 **0 条**；被取代的旧值仍拿 P4（0.716），与当前值（P5，0.750）几乎同权；
同一条记忆被召回 20 次、没有任何新证据，confidence 从 0.775 漂到 0.950。

## 1. 缺陷确认（全部复现过，不是推理）

| # | 缺陷 | 实测 | 根因 |
| :-- | :--- | :--- | :--- |
| D1 | **恒真闸架空评分** | 10/10 用户陈述命中"一手事实" | `TRUST_BY_PROVENANCE[0] === 240 === 闸阈值`，对用户输入恒真；且闸用 `score = max(score, floor)` **改分** |
| D2 | **逐级降档被闸放大成"永不移动"** | 1→2 之后停住 | `nextTier` 一次一级（合理）× 闸 floor P3（不合理）= 永远到不了 3 |
| D3 | **遗忘曲线之外，价值项不随时间贬值** | 400 天旧陈述仍 0.73（P4） | 七因子里六个是静态量，只有 activation 随时间变；静态项足以把分数撑在 P4 |
| D4 | **tInvalid 不进保留度** | 被取代旧值 0.716，与新值 0.750 几乎同权 | `retention.ts` 全文无 `tInvalid`；而召回/合并/抽象三处都在消费它 |
| D5 | **SUPERSEDES 方向写反** | 保护的是新值 | `superseded.add(e.src)`，而 src=新值、dst=旧值 |
| D6 | **P1 与 P2 同 tier** | 墓碑名存实亡 | `tierForDisposition` 把 P2/P1 都映射到 3；`visible()` 也没有 tier 过滤 |
| D7 | **confidence 语义漂移** | 20 次召回 0.775→0.950 | `onRetrieved` 每次 `+0.02×labile`，把"被问得多"兑换成"更可信、更难降档" |
| D8 | **库只进不出** | 无任何自动字节回收 | 降档只改 tier 与向量精度；残差（≈47% 存储）从不释放 |
| D9 | **召回不幂等** | 面板刷新=一次"使用" | `recall()` 无条件更新 tAccess/stability、建共边、推快照 |
| D10 | **URL token 脱敏被切分绕过** | 4 个参数名全明文 | 先切分后脱敏，切走 `?` 后 `[?&]` 锚点失效 |
| D11 | **lockfile 只锁单一平台** | npm 11 `npm ci` 失败 | 未使用的 `esbuild` 把 24 个平台包压成 1 个 |

## 2. 修复方案

### 2.1 闸门：从"改分"改成"封顶"（解 D1 / D2）

```
score  = 七因子 × 陈旧包络           // 永远由公式给出
tier   = tierForDisposition(score)   // 纯映射
闸门    → 只把 P1 挡回 P2（tier 4 → 3）// 不改分
```

- 结果对象同时给出 `disposition`（分数决定）与 `effective`（实际处置），面板两个都显示。
- 第五道闸加两个必要条件：`tInvalid === 0` 且 `support ≥ 3 || accessCount ≥ 3`。
  随口一句不再受保护；被确证/用过三次以上的仍然不删。
- 第六道闸从"仍被其他记忆引用"换成"图式（只增不减）"。
  理由：**墓碑不删行，引用不会悬空**，这道闸没有存在必要；而它留在原地会让所有被图式引用的
  情景记忆永远停在归档层——正是"只进不出"的一半。

### 2.2 陈旧包络：价值必须随时间贬值（解 D3）

```
stale = 0.15 + 0.85 × clamp01(1 − max(0, days−30) / 700)
score = clamp01(retentionScore(parts) × stale + anniversary)
```

30 天内不折损，730 天到地板 0.15。它**不决定档位**，只是把"你早就想不起它了"折算进价值判断：
想不起来的记忆，谈不上多重要。90 天的记忆落在 P3（不归档、不墓碑），400 天落到 P2/P3，900 天可进墓碑。

### 2.3 失效传播（解 D4 / D5）

- `RetentionContext.hasSupersedes` → `isSuperseded`，两处取边改为 `e.dst`。
- `tInvalid` 超过 30 天宽限期 → 强制 `P2 / tier 3`，`protectedBy = null`（闸保护的是**当前**陈述）。
- 移除"版本链环节"闸：被取代本来就该是最强的降档理由。
- `doctor` 增加"已失效但仍在上层"检查，`--fix` 批量归档（存量库迁移）。

### 2.4 墓碑成为真的一层（解 D6 / D8）

| tier | 名称 | 形态 | 召回 |
| :--- | :--- | :--- | :--- |
| 3 | 归档 | 全字段（向量已 PQ） | ✅ |
| 4 | **墓碑** | id + digest + 槽位 + SDR；**残差与向量已释放** | ❌ |

- `visible()` 默认排除 `tier ≥ 4`；`includeTombstones: true` 才翻出来。
- 进墓碑时压实：释放残差（`releaseResidualRef` 在 `putCell` **之后**调用，否则会因为本条还没落库而变成 no-op）、丢弃向量。
- 面板「保留度」页新增「库增长」卡，显示总条数 / 归档 / 墓碑 / KB；墓碑行有「复活」按钮。
- **不删行**：版本链、PART_OF、EVIDENCE 都还在；物理删除仍只能由 `forget --hard --yes` 发起。

### 2.5 confidence 与召回解耦（解 D7）

`onRetrieved` 只更新 stability / accessCount / tAccess；`dConfidence` 在无预测误差时为 **0**。
置信度只能由新证据（support 计数、来源可信度）提升。

### 2.6 召回幂等（解 D9）

`RecallQuery.readOnly`：跳过快照、命中率、tAccess、共激活、面板推送。
面板 / doctor / 解释器一律走只读。

### 2.7 发布工程（解 D10 / D11）

- 脱敏提到切分**之前**（encoder 对整轮原文先 `redact` 再 `segment`），并把 URL token 正则的
  锚点从 `[?&]` 放宽到 `(^|[\s?&])`——规则不该依赖一个会被切掉的字符。
- 删除未使用的 `esbuild` 依赖 → lockfile 平台中立（0 个 `os`/`cpu` 条目）。
- `ci-check-publish` 增加"平台中立性"检查；CI 增加 `npm@latest` 矩阵 job。

### 2.8 选择性完成 M2 / M3

| 项 | v0.5 做法 | 为什么是这一项 |
| :--- | :--- | :--- |
| M2 睡眠重放 | 巩固期按保留度挑选"掉到归档但分数仍 ≥0.45"的记忆，抬回一级（最多 20 条 / 5%） | 降档必须能双向：只降不升，重要但久未提及的记忆会一路滑到墓碑。这是 SWR 重放的选择器，不需要新数据结构 |
| M3 情绪调节 | `AffectPolicy.regulation` 五策略（Gross），按预算/负荷/效价/张力选一条 | "只会表达情绪"是瘸的；调节策略可断言、可解释 |
| M3 特质层 | `affect.trait` 从人格锚 + 关系模型**投影**（Big Five + 依恋） | 单独存一份会出现双真相；投影保证任何时刻可重算 |

未做（明确推迟到 0.6）：CA3 自联想网络 / STDP / DG 神经发生 / 双权重 / 神经三视图 / 自主议程。

## 5. 兼容性与风险

- **存储布局不变**（MC03），旧库不需要 rebuild；新增 tier 4 用的是 tier 字段（u8），不占 flag 位。
- **行为变化是用户可见的**：旧事实会被归档、随口琐事会降档、被取代的旧值不再占热层。
  这是 v0.5 的目的，不是副作用；CHANGELOG 与 README 都写明了。
- **闸只封顶**意味着"分数很低但受保护"的记忆会显示 `P1 分数 / P2 处置`，面板用两栏区分并给出理由。
- **墓碑不可展开原文**：复活只能拿回摘要。这是"墓碑"的本义，也是字节回收的来源。
- 存量库升级：`/mnemo doctor` 会报"已失效但仍在上层 N 条"，`--fix` 批量归档。
