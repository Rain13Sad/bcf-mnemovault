## §2 决策：为什么是"引擎"，不是"更多适配器"

路线文档 §2.3 的结论是对的，本版把它执行到底：

> **"适配所有大模型"不是目标，是门票。**

所以 v0.6.0 不做"支持 N 家模型"的宣称，而是做**一件让适配变得廉价的事**：
把内核与外部世界之间那层"谁提供向量 / 谁提供 token 计数 / 谁提供时间"抽成端口。

于是新增一家模型 = **加一行数据**（`MODEL_PROFILES`），不是加一个分支。

### 2.1 三层职责

```
core      同步内核（零第三方依赖）        ← 只认端口，不认识 Cordis / HTTP
llm       本版新增：HTTP → 端口          ← 只认宿主
host      DSH / MCP / 你的 Agent          ← 只认引擎
```

### 2.2 一条不能破的约束：内核必须保持同步

`recall()` / `ingest()` 是同步的，这是确定性重放与内容寻址的前提（v0.1 起）。
而 HTTP 模型是异步的。**本版的解法不是把内核改成 async，而是"预热缓存"**：

```
异步侧 prime(text) → 缓存 → 同步侧 peek(text) → 命中用 provider 向量，未命中退回哈希
```

好处：await 不泄漏进内核，降级可观测（`counters.embedMiss`），
坏处：**首轮可能拿不到真向量**（缓存空）。这条写进了面板的"限制"清单，不藏着。

### 2.3 向量空间的硬闸（本版最重要的一条正确性判据）

换 embedding 模型 = 换向量空间 = **必须重算全库**。这是 dense 路线的固有成本。
如果拿 provider 查询向量去打哈希库，余弦相似度仍然返回 0~1 的数，**但那个数没有意义**——
召回会悄悄变差，而没有任何错误。

所以判据写死成一条：`memory.embSpace === port.space` 才允许用 provider 向量。
想让 provider 生效，唯一的路是 `engine.reembed()` 把全库换过去；
`reembed` 分批、游标存 meta、**全部跑完才切换空间**（不留半个库）。

> 开发中这里一度放过"库还是哈希空间"的情况（想省掉一次重算），
> 被 `test/v06-engine.test.mjs` 的"空间不一致时必须退回哈希"抓住。

## §3 情感记忆的四条机制（研究 → 代码 → 断言）

这一节是本版"情感"部分的全部内容。四条机制都有明确出处，且都写成了可断言的性质。

| # | 机制 | 研究依据 | 代码 | 可断言的性质 |
| :-- | :--- | :--- | :--- | :--- |
| ① | 评价 → 核心情感 | Scherer SEC / OCC → PAD | `padFromAppraisal` | 目标受挫必须降效价；受挫不比推进更平静 |
| ② | 心境一致性 | Bower mood-congruent memory | `moodCongruence` | **负向侧打折 0.7**（反刍闸）；低显著度不吃增益 |
| ③ | 唤醒调制巩固 | Yerkes-Dodson / 杏仁核调制 | `arousalBoost` | **倒 U**：峰值在 a=0.5，两端回落到 0.85 |
| ④ | 情感作为信息 | affect-as-information | `emotionBrief` | 字节稳定（否则 prefix cache 全失效） |

### 3.1 为什么②要**不对称**

难过时更容易想起难过的事——这是真实的，也是**危险的**：
召回会经再巩固加强效价，形成正反馈。v0.5 只靠 `wAffect ≤ 0.25` 封顶，
长会话里仍会漂向"越聊越丧"。本版加两道闸：

1. `moodCongruence` 负向侧乘 0.7
2. `dampedAffectWeight`：最近 4 轮以上、负面占比 > 50% 时，把 `wAffect` 再折，最低到 40%

### 3.2 为什么③不是线性的

"越激动越重要"是错的。极高唤醒下记忆会**碎片化**（细节在，顺序没了）——
把争吵写成里程碑，正是这条线性假设的后果。所以用 `4a(1−a)`：峰值 1、端点 0。

### 3.3 情感摘要（进 prompt 的那一行）

```
A|mood:-0.42/0.61/-0.20|lab:难过0.51,无力0.24|rel:t72,f55|open:1|hint:先接住情绪再谈事
```

约 30 token，格式与 MRS 一致。它回答模型三件事：现在什么心情、为什么、该怎么说话。
**不说**"你应该感到…"——所有输出都是状态变量的投影，不是主观体验（边界与 v0.5 一致）。

## §4 六项创新的取舍

路线文档给了 I1–I6。本版做三个半，其余明确推后。

| 创新 | 本版 | 做到什么程度 | 为什么停在这 |
| :--- | :--- | :--- | :--- |
| **I1 记忆护照** | ◐ 半 | 空间标记 + `reembed()` 可续重算 + 空间不匹配硬闸 | `.mnp` 容器与跨设备迁移是 v1.0 的事；先把"换模型不静默出错"做对 |
| **I2 遗忘作为第二器官** | ◐ 半 | `engine.forget()` 返回**删除回执**（digest + proof + 悬空引用数） | 保留策略 DSL 与 ForgetEval 进 CI 是 v0.9 |
| **I3 状态化召回** | ✗ | 未做 | 需要 `state ∈ {effective, superseded…}` 进 `recall()` 返回值，会改冻结契约 |
| **I4 可复现评测包** | ✗ | 未做 | 本版没有新的对外分数，也就不需要新的复现工具 |
| **I5 跨模型编译器** | ✅ | `compile()` 三闸（能力/token/价格）+ 跨模型成本表 | 这是"适配常用大模型"最直接的产品化 |
| **I6 结构化码本** | ✗ | 研究项，不排期 | 必须先证明"随机码本 + 倒排已经不够快" |

### 4.1 I5 的三闸顺序（先降格式，再丢条目）

```
① 能力闸：模型 strongSchema=false → 直接 prose（不让弱模型看天书）
② token 闸：超预算 → 先试 compact（省 25%），仍超则从尾部丢条目
③ 价格闸：超 maxPrice → 继续丢，直到成本达标或只剩图例
```

顺序反了会得到"只剩 2 条但用了 2.5× token"的荒谬结果。
价格闸用**钱**而不是 token，因为 B 端采购看得懂"每轮不超过 ¥0.0003"，看不懂"320 token"。

## §5 面板：为什么是 3D 星图与调控台

### 5.1 星图：3D 不是装饰，是**信息**

记忆相似度是 64 维的。压到 2D 时，两簇本来正交的记忆会被投到同一条线上，
看起来"有关系"——这是 2D 图谱最常见的误导。3D 只多一个轴，但保留了"绕过去看另一面"的能力。

三个工程决定：

| 决定 | 理由 |
| :--- | :--- |
| **随机投影**（固定种子）而不是 PCA | PCA 的主轴会随新数据旋转 → 整张星图突然转一下，用户以为记忆被改了。随机投影只加点、不移动旧点 |
| 投影在 **host 侧**算 | 客户端拿不到 64 维向量，也不该拿（快照已经有 20+ 字段） |
| **canvas** 而不是 SVG | 1200 节点 + 2400 边，SVG 每帧重建 3600 个 DOM，掉到 10 fps |

星图是**星等采样**，不是目录：固定的、高重要的、带情绪的必须出现；
`sampled/total` 如实标在标题栏。

### 5.2 调控台：先算再改

v0.5 的设置页是"配置项的镜子"。调控台改成"参数 → 后果"的显式化：

- 每个旋钮旁边实时显示它对 **token/轮** 与 **成本** 的影响
- 提交前可 dry-run；提交后即 `preset=custom`（不会被预设覆盖回去）
- 引擎卡片与旋钮**同屏**：预算紧了可以少给记忆，也可以换便宜模型——这是同一个决策的两面

只放 16 个旋钮。`dbPath` / `embDim` / `sdrK` 这类要重启或重建的一律不进来——
把它们做成滑杆，就是在骗用户"拖一下就好了"。

### 7.1 一处必须写明的口径变更

1 万 cell 的召回 p95 从 v0.5.2 的 25 ms 变成 45–55 ms。原因不是变慢，是**这一档测的东西变了**：

| | v0.5.2 | v0.6.0 |
| :--- | :--- | :--- |
| 语义路 | HNSW（`annThreshold=2000`） | **精确扫描**（`annThreshold=20000`） |
| 候选池 | ~128 条 | 6000+ 条 |
| p50（安静进程） | 37 ms | **11 ms** |

HNSW 在这个规模上更慢，所以阈值被提到它真正开始赢的地方。门槛 40 → 60 ms 是口径变更，
同时写进了 README、门槛脚本注释与 CHANGELOG 首段——**不静默调**。

## §8 风险与不成立条件

| 风险 | 征兆 | 应对 |
| :--- | :--- | :--- |
| **预热缓存让首轮退化** | `counters.embedMiss` 高、`usedProvider=false` | 面板"引擎"卡片显示命中/未命中；`prewarm=false` 可关 |
| **provider 向量与库空间不一致** | 召回分数分布异常但无报错 | 空间硬闸（§2.3）+ reembed 跑完才切换 |
| **价格闸挡住正常使用** | `fits=false` 频繁 | `maxPricePerTurn=0` 即不限；面板显示每次编译成本 |
| **3D 星图在小库上无结构** | 点数 < 3 时看不出团 | 空态直接说"先聊几句"，不画一个假星系 |
| **`reembed` 用 digest 而非原文** | 语义质量低于理想值 | 这是刻意的：原文在残差里，取出来慢 10 倍；写在限制清单里 |

**不成立条件**：如果宿主开始提供统一的 embedding 服务（所有模型同一空间），
§2.3 的空间闸会退化为恒真，`reembed` 变成死代码——那时应当删掉它，而不是留着当仪式。

## §9 明确不做（写得比做更重要）

1. **不做托管云服务**。与"本地优先、零依赖"直接冲突。
2. **不发明第五个记忆协议**。MCP 的四个动词（add/search/list/delete）是入场券，不是优势。
3. **不声称 SDR 取代 embedding**。只声称"符号路的码本与模型无关，语义路可插拔"。
4. **不把"已支持 X 模型"写成营销语言**。支持列表是数据表，能力边界在面板的限制清单里。
5. **不为了好看做 2D→3D 的平移**。3D 的唯一理由是"绕过去看另一面"这件事本身是信息。
6. **不做 AGI / 意识相关宣称**。所有情感输出都是状态变量的投影。
